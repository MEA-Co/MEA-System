# 학교 편제표 가져오기

선택과목 화면의 `직접 선택` 탭과 독립적으로 학교 공시 원문을 조회하고 검토한다. 탭을 바꿔도 입력 상태는 유지되며, 가져온 선택군을 수동 입력의 학기별 단일 선택 개수로 합치지 않는다. 직접 입력과 가져오기 결과는 확정 시 동일한 학기·학교지정 과목·선택군 모델로 정규화되며, 설정 화면을 닫고 희망 학과 및 편제표를 보여주는 과목 선택 단계로 이동한다. 확정한 결과와 희망 학과는 현재 화면 메모리에만 유지된다. `결과 저장`으로 원문 출처·해시·검증 결과·검토 여부를 포함한 JSON을 내려받는다. DB 저장은 하지 않는다.

## 환경 변수

- `OPENAI_API_KEY`: 문서 분석에 필요. 기존 서버 환경 변수를 사용한다.
- `SCHOOLINFO_API_KEY`: 선택 사항. 설정하면 공식 학교기본정보 API(`apiType=0`)를 조회한다. 없으면 공개 검색 화면의 학교 검색 JSON을 사용한다.
- `SUBJECT_EXTRACTION_MODEL`: 선택 사항. 문서 추출 기본값은 `gpt-5.6-sol`. PDF 입력과 Structured Outputs를 지원해야 한다. 과목 비교 설명 모델과는 별도 설정이다.

## 조회 경로

공식 Open API의 제공 목록에는 교육과정 첨부파일이 없다. 공시 원문은 학교알리미 공개 화면의 다음 경로에서 가져온다. 공개 화면용 엔드포인트는 공식 Open API 계약이 아니므로 사이트 변경 시 어댑터를 수정해야 한다.

1. `/ei/ss/pneiss_a04_s0/getSchoolList.do`: EUC-KR 학교명으로 검색하여 공시 UUID 확보.
2. `/ei/pp/Pneipp_b14_s0p.do`: `학교교육과정 편성·운영 및 평가에 관한 사항` (2-가) 공시.
3. `#eiFileDownForm`과 `getEiFile14(FILE_SEQ)`에서 다운로드 매개변수 확보.
4. `/servlets/EiFileDownLoad.do`: 선택한 원문 다운로드. 분석 요청 때 서버에서 목록을 재조회하며 임의 URL은 받지 않는다.

파일명 점수는 추천 순서일 뿐이다. 학사일정도 목록에는 남겨 사용자가 원문을 확인할 수 있다. 편제표 여부와 코호트는 실제 문서 분석에서 다시 확인한다.

일반 과정은 기본 편제로 간주해 학년·학기 구조가 맞으면 가져온다. 과학중점 과정은 일반 과정 표가 섞일 수 있으므로 과정 표지 또는 과학·수학·정보 이수 조건을 원문 근거로 확인한 경우에만 확정한다.

## 추출과 검증

- 매직바이트와 ZIP/OLE 내부 구조로 PDF, HWP5, HWPX, XLS/XLSX, DOCX, HTML 표를 구분한다.
- PDF는 텍스트와 페이지 이미지를 함께 읽을 수 있도록 원문 파일 입력을 사용한다. Excel은 셀과 병합 범위를, HWPX/DOCX는 XML 구조를 전달한다.
- HWP5는 LibreOffice로 PDF 변환을 먼저 시도해 페이지와 표의 시각 구조를 분석한다. macOS에서는 `/Applications/LibreOffice.app/Contents/MacOS/soffice`를 우선 사용하며, 다른 환경은 `SOFFICE_PATH`로 지정할 수 있다. 변환 결과가 120쪽을 넘으면 표가 깨져 비정상적으로 분할된 것으로 보고, 압축 스트림·레코드 계층 텍스트 추출로 fallback한다. 큰 원문은 교육과정·편제·학점 표제 주변을 우선 분석한다. HWP 원본은 변환 성공 여부와 무관하게 원문 대조를 요구한다. 암호화·배포용 HWP는 거절한다.
- 과목 학점, 학교지정 여부, 선택군, 택 N, 후보 수 원문 근거, 연동 규칙, 코호트와 원문 위치를 구조화한다. 없는 값은 null/unknown으로 남긴다.
- 서버가 중복, 선택군 연결, 후보 수, 코호트, 학점 합계를 검사한다. 학점은 필수 과목 + 선택군별 `택 N × 학점`으로 계산한다. 후보마다 학점이 다르거나 복합 규칙이면 임의 계산하지 않는다.
- 모든 추출 학기의 교과 총계와 2-1~3-2 자료를 확인한다. 창체 포함 총계를 교과 총계로 비교하지 않는다. 불명확한 결과는 검토 확인 후에만 수동 확정할 수 있으며 자동 검증 상태는 바꾸지 않는다. 코호트 불일치·미확인과 추출 실패는 확정을 막는다.
- 12MB 원문, 32MB 압축 해제, 24만자 구조화 원문 한도를 둔다. 큰 문서는 편제표 부분을 따로 업로드한다. 서버 인증 및 회원 역할 검사를 사용한다. 프로세스별 사용자 동시 분석은 1건으로 제한한다.

원문 식별과 값의 의미 해석은 모델 추출에 의존한다. `verified`는 추출 근거와 서버의 구조·산술 검증을 통과했다는 의미이며, 원문 대조 없이 정확도를 보장하는 표시는 아니다.

## 전공 연계 과목 선택

편제표 확정 후 희망 학과를 입력하면 `recommendations.ts`의 내부 우선순위 분류 중 가장 가까운 분류를 찾는다. 내부 `Core`만 필수 선택으로 취급하고, `Sub core`와 추천 과목·과목군은 안내로 표시한다. `미기`는 `미적분 II`와 `기하`, `미`는 `미적분 II`, `생물`은 `생명과학`으로 정규화했다.

고려대, 연세대, 경희대, 중앙대의 2028학년도 자료는 대학별 모집단위와 개별 과목 또는 과목군 규칙으로 저장한다. 희망 학과와 충분히 유사한 모집단위가 있는 대학만 표시한다. 경희대의 대학 `핵심과목`은 강한 안내 표시는 제공하지만 내부 `Core`가 아니면 강제하지 않는다. 연세대의 과학 진로선택 3과목 이상과 같은 과목군 조건은 해당 과목군의 편제 과목에 표시한다.

학생 선택은 학교 선택군별 `택 N` 상한을 넘지 못하며, 같은 과목이 여러 학기에 있으면 한 학기의 과목만 선택 상태로 유지한다. 아직 DB에는 저장하지 않는다.

## 화면 코드 구조

### AI 비교 설명

상담 진입은 세 가지로 나눈다. `두 과목 중 고민`은 선택 과목과 미선택 과목을 직접 지정한다. `꼭 들어야 하나요`는 미선택 과목의 내부 우선순위를 먼저 안내한 뒤 교체할 2단계 선택 과목을 고른다. `안 들어도 괜찮나요`는 2단계 과목의 안내 후 대안을 고르거나 추천받는다. 초기 안내는 로컬 정책·과목 목록 기반이며 AI 호출은 최종 비교에서만 발생한다. 학기·선택군·학점·이수조건 검증을 통과하는 교체만 제공한다.

일반 고민은 전공 연결·탐구 방향을, 성적 고민은 부담의 대상과 예상의 근거를 중심으로 설명한다. 성적 걱정만으로 대안 점수를 올리지 않으며, 명시적으로 지정한 대안이 더 유리하다는 학생의 예상이 있을 때만 기존 조언 가중치를 적용한다. 예상 등급을 실제 성취나 입시 유불리로 단정하지 않는다.

2단계 상담의 `비교하기`에서 후보 최대 2개를 `/api/consulting/subject-selection/compare`로 한 번에 보낸다. 전공, 현재 선택·고정 과목명, 후보별 고민 이유, 규칙 기반 추천과 주의 사항만 전달하며 학교명·학생 식별자·전체 대화는 모델에 전달하지 않는다. 서버는 로컬 과목 목록의 설명·주요 영역과 내부 전공 정책을 추가한다. 모델에는 실제 교과 내용과 탐구 연결 제안을 구분하고, 성적 예상이나 입시 결과를 단정하지 않도록 지시한다.

`OPENAI_API_KEY`를 사용하며 모델은 `SUBJECT_COUNSELING_MODEL`로 지정한다(기본 `gpt-5.6-luna`). 응답은 구조화된 설명만 반환하고 과목 변경 권한은 없다. 교체 검증은 기존 `swapProblem`이 담당한다. 실패 시 기본 비교를 유지하며 버튼으로 재시도한다. 입력 변경 시 이전 요청을 취소하고 오래된 결과는 표시하지 않는다. 같은 입력은 해당 상담 화면 메모리에서 최대 20개까지 재사용한다.

서버는 기존 회원 인증, 64KB 요청 한도, 사용자당 동시 1건·5초 간격 제한을 적용한다. 호출 제한은 프로세스 메모리 기준이며 다중 인스턴스 운영 시 공유 제한 저장소가 필요하다. 모델 응답은 `store: false`로 요청하고 DB에 저장하지 않는다. 자유 질문은 이번 연결 범위에 포함하지 않는다.

비교 검증: `node --test scripts/verify-course-swap.mjs`. 실제 모델 확인: `SUBJECT_COMPARISON_LIVE=1 node --env-file=.env --test --test-name-pattern="live AI comparison" scripts/verify-course-swap.mjs`.

`app/(private)/consulting/subject-selection`은 머티리얼 박스와 동일하게 화면과 화면 내부 UI를 구분한다. 공통 `ConsultingFlow`의 plan/renderer 이식은 이번 분리 범위에 포함하지 않는다.

필수 선택 상태는 화면이 아닌 상위 세션에서 실행하는 훅이 소유한다. 필수 확정 화면을 닫아도 세션은 유지되며, 초안은 확정 과목을 전달받는다. 자유 질문은 템플릿을 전환해도 마운트를 유지한다. 훅/계산 모듈은 화면 컴포넌트를 가져오지 않는다.

정책 데이터·공통 도메인 판정·서버 분석은 `features/subject-selection`에 유지한다. 대학별 충족 여부는 안내·최종 확인·교체 비교에서 `university-status.ts`를 공유한다.

## 복수 학과 준비 깊이

`review`(조정 검토)에서만 `_lib/major-review-screening.ts`로 연결 기반과 코어 개설 여부를 먼저 확인한다. 연결 기반은 공통 코어·심화 2과목 이상 또는 `major-relationships.ts`에 등록된 연구 방법 연계의 과목 조건이다. 구체적인 조합과 판정 순서는 [복수 학과 기준](./major-relationships-policy.md)을 따른다. 현재 선택만이 아니라 1학년 지정·학교지정·전체 선택 후보를 보므로 아직 선택하지 않은 공통 과목도 반영한다. 어느 연결 경로도 확보할 수 없거나 편제 전체로도 코어 조건을 채울 수 없으면 질문 없이 기존 전공 기본안 또는 다른 학과 검토로 안내한다. 별도 이유 입력으로 이 권고를 우회하는 흐름은 두지 않는다. 이 사전 검토는 동시 배치 가능성을 보장하지 않고 실제 선택군·선행·졸업요건 검증은 기존 조정안 탐색이 맡는다.

검토 가치가 있으면 `MajorIntentReview`에서 지원 의향만 확인한다. 실제 지원 관심이 있거나 아직 결정하지 못한 경우 모두 과목 조정안 탐색으로 진행한다. 탐구 확장 목적은 기존 전공 기본안으로 안내한다. 서술형 답변과 AI 지원동기 심사는 사용하지 않는다. 구체적인 교체 과목을 확인하고 학생이 동의해야 적용한다. `compare` API는 과목 비교 설명만 담당한다.

복수학과의 추가 추천 점수는 기존 학과 × 1.5 + 추가 학과 × 1로 고정한다. 기존 코어와 확정 과목 보호 및 조정안 재검증은 별도로 유지한다.

`_lib/major-depth.ts`는 코어 충족과 준비 깊이를 별도로 평가한다. `science-sequence.ts`의 과학 영역 연결을 공유하며, 핵심 또는 Sub core에 화학이 있으면 물질과 에너지·화학 반응의 세계를 해당 영역의 심화로 인정한다. 넓은 추천 영역인 ‘과학’만으로는 모든 과학 심화를 인정하지 않는다. 기초 과목이 없는 심화는 깊이 계산에서 제외하고 코어·선행 재검토로 안내한다.

심화는 필수 코어에 포함되어도 깊이로 인정한다. 선택형 코어는 하위 영역 조건을 포함한 최소 개수만 예약하고 초과 이수를 추가 보완으로 표시한다. 코어 외 추가 보완 수는 참고 지표이며 필수 통과 조건이 아니다. 같은 과목은 전공별로 한 번만 세되 양쪽 전공에 관련된다면 각각 인정한다. 화면에는 각 과목의 인정 근거도 표시한다.

깊이 과목 수, 단일 전공 자동 초안 대비 유지율, 공통 기반 개수는 메아의 임시 상담 기준이다. 대학 요구나 합격 가능성 판정이 아니며, 현재 자동 초안 탐색 실패를 모든 편성 조합의 불가능으로 해석하지 않는다.

`_lib/confirmed-adjustment.ts`는 최대 3회 교체·200개 상태에서 1단계 조정안을 탐색한다. 같은 학기/선택군/학점 교체만 허용하며 기존 코어(선택형 포함), 선행 관계, 기존 교체 검증기가 지원하는 영역별 학점·학교별 최소 과목 수를 보호한다. 조정 전 단독안을 기준으로 깊이 유지율을 계산하고, 병행 준비 판정을 통과하는 경우만 제안한다. 미지원 원문 규칙과 실제 시간표는 별도 확인이 필요하다.

명시적 동의 후 적용 직전에 현재 확정 ID와 교체 조건을 다시 검증한다. 변경은 세션의 확정·잠금 상태에 반영하며 2단계 교체/되돌리기 이력을 초기화한다. 취소는 기존 선택을 유지한다. 탐색에 실패해도 병행 불가능을 단정하지 않는다.

졸업요건 보충은 `_lib/graduation-compensation.ts`에서 별도로 탐색한다. 교체로 부족해지는 예술·통합 영역 학점과 지원되는 학교 조건을 3-2 → 3-1 → 2-2 → 2-1 순서의 빈 선택 자리로 보충한다. 한 과목으로 부족하면 여러 과목을 추가하며, 특정 학기 조건은 다른 학기로 옮길 수 없다. 탐색은 교체별 최대 200개 상태로 제한한다. 보충은 1단계 확정으로 잠기며 교체와 함께 동의·재검증 후 한 번에 적용한다. 조정안 표시는 `_screens/_components/ConfirmedAdjustmentSummary.tsx`로 분리한다.
