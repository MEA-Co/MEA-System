# 전공 가치관 탐색

## 연결한 기존 입력과 메타데이터

브랜딩의 `values-guide` 설명 뒤 `values` 화면을 확장했다. 재료함 및 `features/exploration` 코드는 가져오지 않는다. 공통 엔진에는 특정 컨설팅의 질문·분석 규칙을 넣지 않는다.

학생 입력은 기존 확정 `majors.id`·대표명·1~3순위, `[전공명]\n키워드` 형식의 Flow 산출물에서 연결한다. 관심사마다 별도의 ID를 부여하여 같은 문자열도 전공·순위별로 보존한다. 자유 입력은 `keywordId=null`로 사용한다. 검색 사전이나 키워드 ID 연결을 강요하지 않는다. 입력 원문은 변경하지 않으며 이후 설명은 observation, 실제 발언은 conversation에 기록한다. 현재 이전 단계에는 관심 이유 필드가 없지만 입력 계약의 `priorReason`이 있으면 이전 학생 발언으로 포함한다.

기존 산출물 `/Users/mealdm/Documents/Codex/2026-09-14/x20/outputs/value_exploration_metadata/`의 README, 활용·결합 규칙, 실제 스키마 및 조회 SQL을 확인했다. 원격 Data API의 실제 테이블 구조도 확인했으며 메타데이터를 재생성하거나 DB 구조를 변경하지 않았다.

서버의 `get_major_value_context(p_major_ids, p_include_keywords=true)` 호출로 기존 전공 설명·키워드·예시와 disciplinary perspective, inquiry dimensions, effective thinking modes, value lenses 및 core value references, value tensions를 함께 조회한다. `inherit/refine/add` 및 부모를 대체하는 결합은 기존 RPC/뷰에 맡긴다. 전공 렌즈에 부모의 core value를 임의로 합치지 않는다.

서버 함수는 로그인·온보딩 및 consultant/admin 권한을 확인한다. 제품의 조회에는 로그인 사용자의 Supabase 클라이언트를 사용하여 SECURITY INVOKER/RLS를 유지한다. 서버 키를 브라우저에 전달하지 않는다. 선택한 전공 이름·ID와 선택적 keywordId 소속도 조회 시 검증한다.

## 동작

1. 기존 관심사와 순위를 보여주고, 1순위부터 기본 질문을 시작한다. 순위는 분석 가중치가 아니다. 다른 관심사부터 이야기할 수 있다.
2. 왜 그 키워드에 관심이 있는지 먼저 묻고, 학생이 말한 계기·끌리는 이유에서 중요한 기준과 방향으로 대화를 이어간다. 키워드의 뜻이나 궁금한 부분은 관심 이유를 이해하는 데 필요한 경우에만 보조적으로 확인하며, 한 번에 핵심 질문 하나를 묻는다. 순수한 원리 이해·해석 관심도 허용한다. 단순히 궁금하다는 답은 관심 초점으로 남기며 가치관으로 즉시 승격하지 않는다.
3. 연결 가능성이 있으면 AI는 잠정 연결만 제시한다. 학생이 연결을 확인하거나 분리한다. 다른 전공의 동일 키워드도 자동으로 합치지 않는다.
4. 관심사마다 미탐색·추가 이유 필요·남은 확인 사항·탐색·확인된 공동 탐색·학생의 건너뛰기를 구분한다. 조기 종료 시 미탐색 영역을 남긴다.
5. 관심사별 방향·이유와 공통/고유/조건부 결과를 표시한다. 근거 발언을 펼쳐 볼 수 있으며 문장과 조건·예외를 수정하거나 결과를 제외할 수 있다. 수정 중인 문장·조건도 저장되며 반영 또는 취소 전에는 다음 단계로 넘어가지 않는다. 수정한 결과는 다시 학생 확인이 필요하다. core value 태그는 내부 보조 참조이며 개인 표현을 사전 어휘로 바꾸지 않는다.
6. 모든 유지할 결과를 확인하면 기존 `outputs.values`에 확인한 개인화 문장·조건·남은 관심사를 전달하고 역량 단계로 이동한다. 근거가 없으면 '더 확인이 필요하다'는 상태로도 진행할 수 있다.

## 상태·근거·오류

- `features/major-values/domain.ts`: 입력·상태·AI 출력 계약, 참조 검증, 학생 조작, 종료 및 결과 생성.
- `metadata.ts`, `metadata-server.ts`: 실제 RPC 응답 검증·결합 조회.
- `prompts.ts`, `coach.ts`, `actions.ts`: 질문·해석 지침, 구조화 응답, 인증 및 AI 실행. `OPENAI_MAJOR_VALUES_MODEL`로 모델 설정, 기본 `gpt-5.6-luna`.
- `components/`: 대화·관심사 상태·연결 확인·결과 수정 UI.
- `session.ts`: 기존 Flow draft와 같은 탭의 sessionStorage 저장·재개.

모든 인용은 실제 student 발언 ID와 일치하는 원문 부분 문자열이어야 한다. AI 질문·메타데이터·건너뛰기·제외 지시는 가치관 근거가 될 수 없다. 존재하지 않는 관심사·core value·메타데이터 ID, 관심사 누락, 학생이 확인하지 않은 공동 가설, 다른 관심사의 근거 복제, 동일 발언을 중복 계산한 공통 패턴을 차단한다. 공통 패턴은 실제 답변·이전 이유·학생 수정의 서로 다른 발언이 필요하며 단순 확인 클릭을 독립 근거로 세지 않는다.

AI 출력은 전체 유효 가설 스냅샷이다. 바뀐 결과의 확인 상태는 해제하고 제거된 가설은 남기지 않는다. 제외한 해석과 분리한 연결은 새 ID만 붙여 되살리지 못하도록 검증한다. 학생이 묶음을 분리하면 해당 공동 가설을 제거하고 관련 방향과 이유를 재확인 상태로 바꾼다.

발언은 AI 요청 전에 ID와 함께 저장한다. 실패하면 pendingTurnId와 발언을 그대로 유지하여 재시도 시 중복 추가하지 않는다. 출력 검증 실패는 유효 ID 목록과 함께 한 번 교정 요청하고, 다시 실패하면 화면에서 재시도한다. 늦게 돌아온 응답은 떠난 화면에 반영하지 않는다. 자동 전송 시 한글 조합 중 Enter는 무시한다.

## 저장과 재개 범위

DB에 새 학생 기록 테이블은 추가하지 않았다. 기존 Flow draft에 전체 상태를 보존하고, 사용자 ID와 입력 묶음으로 분리한 sessionStorage에 병행 저장한다. 저장된 최신 탐색은 브랜딩 시작 화면의 '가치관 탐색 이어하기'로 전공·키워드를 재입력하지 않고 복원한다. 브랜딩 전용 재개 Plan이 입력 맥락을 복원하므로 공통 엔진의 저장 구조는 바꾸지 않았다. 같은 이름·키워드라도 원문·순위가 바뀌면 다른 맥락으로 시작한다.

이 저장은 같은 브라우저 탭 범위다. 탭 종료 후 장기 보관, 다른 기기 공유, 학생별 서버 영속 저장은 제공하지 않는다. 같은 컨설턴트 계정에서 다른 학생을 진행할 때는 '새 탐색 시작'을 사용한다. 저장이 실패하면 현재 화면의 상태는 유지하고 안내를 표시한다. 전체 검토의 샘플 대화는 사용자 저장 공간에 쓰지 않는다. 기존 단일 요약 형식 초안은 실제 대화와 작성 중 입력을 보존해서 변환하되, 예전 AI 요약을 학생 발언으로 취급하지 않는다.

## 검증

- `node --experimental-strip-types --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test scripts/verify-major-values.mjs`: 17개 상태·근거·수정·복원 테스트 통과. 첨부 지침의 9개 대표 상황을 가상 발언/응답 fixture로 검증한다.
- `node scripts/verify-major-values-plan.mjs`: 실제 Consulting Agent로 저장 입력 복원 및 values → competencies → values → keywords → values-guide → values 전환·입력 보존 검증 통과. 테스트 도구 위치는 `TEST_TOOLS`(기본 `/tmp/major-search-validation`).
- `node --env-file=.env --experimental-strip-types --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/verify-major-values-metadata.mjs`: 원격 DB의 컴퓨터·소프트웨어공학/심리학 조회 및 실제 반환 계약 통과. 버전 `value-exploration-2026-09-16-v1`, 각 전공 관심 차원 3개·렌즈 4개·긴장관계 3개. 읽기 전용 서버 키 검증이며 실제 로그인 세션에서 RLS까지 검증한 것은 아니다.
- `node --env-file=.env --conditions=react-server --experimental-strip-types --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/verify-major-values-live.mjs`: 실제 메타데이터와 AI 모델로 합성 사례 3개를 확인했다. 복수 전공 사례는 초기 참조 오류와 관심/가치 구분 문제를 보완한 후 재검증하여 통과했다. 동일 블랙홀 관심에서도 이론의 일관성과 관측 근거가 다른 질문·해석으로 나왔다.
- 브라우저 테스트 `scripts/verify-major-values-browser.mjs`는 실패 답변 보존·재시도·새로고침 복원·건너뛰기·수정·확인 시나리오를 작성했다. 실행 권한 승인이 거절되어 완료하지 못했다.

위 검증은 구현 및 가상 대화 검증이다. 실제 학생 대상 효과·타당성 검증은 아니다. 원문 존재와 참조 구조는 결정적으로 검사하지만, 발언이 해석을 의미적으로 충분히 뒷받침하는지는 AI 해석과 학생의 확인에 의존한다. 대화 길이/응답 한도, 모델의 질문 품질, 다중 턴에서의 해석 변경은 지속적인 검토가 필요하다.

## 대표 동작 예시 — 합성 대화

입력: 1순위 컴공(HCI, 그래픽), 2순위 심리학(인지 과정, 의사결정).

1. MEA: “HCI와 그래픽에 왜 관심이 있나요? 관심을 갖게 된 계기나 마음이 끌리는 이유를 편하게 들려주세요. 키워드마다 이유가 달라도 괜찮아요.”
2. 학생: “앱에서 사람들이 왜 헷갈리는지 이해하는 과정이 좋아요.” → HCI의 이유를 근거 발언과 함께 기록한다. 나머지 세 관심사는 유지한다.
3. 학생: “인지 과정과 의사결정도 실제 사용자가 생각하는 이유를 이해하고 싶어서예요. HCI와 같은 이유로 이어져요.” → 잠정 연결을 보여주며 학생이 '연결돼요'를 누른다.
4. 그래픽은 학생이 '건너뛰기'를 선택한다. 공통 묶음에 넣지 않는다.
5. 결과: “실제 사용자의 생각과 경험이 생기는 이유를 이해하는 데 의미를 둔다.” 적용 범위는 HCI·인지 과정·의사결정이며 실제 발언 두 개를 근거로 보여준다. 그래픽은 '건너뜀'으로 남긴다.
6. 학생이 문장·조건을 수정하거나 제외할 수 있다. '내 생각과 맞아요'로 확인한 뒤 다음 단계로 이동한다.

이 예시는 상태 전환 테스트의 가상 사례다. 실제 AI 표현은 대화와 응답에 따라 달라진다.
