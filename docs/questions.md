# 질문·질문지 관리

질문지는 `questionnaires`, 원본 질문은 `questions`가 본체이며 별도 버전을 만들지 않는다. 데이터 계약은 [저장 구조](questionnaire-storage-design.md), 최신 운영 적용 상태와 배포·검증 절차는 [운영 안내](questions-operations.md)를 따른다. 아래 이전 날짜의 운영 적용 대기 기록은 당시 상태다.

## 서술형 탐구활동 참조 권장

각 서술형 답변 열의 설정에 `탐구활동 참조 권장` 체크박스를 둔다. 기본은 해제이며 체크/해제를 저장·재조회할 수 있다. 옵션을 켜면 질문 및 질문지 미리보기의 해당 답변 입력에 포커스하면 파란 테두리와 파란 말풍선을 표시한다. 말풍선은 `탐구활동 참조가 필요한 질문입니다.`와 `@탐구활동 을 입력하여 탐구활동을 언급하며 답변해주세요!` 두 줄이며 포커스를 벗어나면 숨긴다. 다른 답변 유형으로 바꾸면 옵션을 제거한다. 권장 안내이며 탐구활동 첨부를 필수로 요구하지 않는다.

설정은 기존 `questions.fields` JSONB의 `explorationRecommended` boolean으로 저장한다. API 스키마와 DB 검증 함수가 서술형에만 허용한다. 기존 필드에 속성이 없으면 해제로 해석하며 데이터 일괄 변경은 하지 않는다. 로컬 migration `20261001034040_question_text_exploration_recommendation.sql`, 운영 순서는 `questions-operations.md`의 같은 날짜 절을 따른다.

## 진입점과 파일 구조

대시보드 페이지 키는 `questions` 하나다. 이전 `view=questionnaire` 접근 항목·별도 렌더러·아이콘·호환 분기는 제거했다. 이전 URL은 다른 미지원 view와 같이 역할별 기본 화면으로 처리한다. `questionnaires` 탭 값과 `/api/questionnaires`는 현행 질문지 기능이므로 유지한다.

| URL (`/dashboard` 기준)                                       | 화면                                                        |
| ------------------------------------------------------------- | ----------------------------------------------------------- |
| `?view=questions`                                             | 리드·관리자: 질문 관리 대시보드. 컨설턴트: 기존 배포본 목록 |
| `?view=questions&tab=questions`                               | 질문 목록                                                   |
| `?view=questions&question=<ID 또는 new>`                      | 질문 생성·수정 Drawer                                       |
| `?view=questions&tab=questionnaires`                          | 내 질문지 목록                                              |
| `?view=questions&tab=questionnaires&draft=<버전 ID 또는 new>` | 질문지 편집·조회                                            |
| 위 상세 URL에 `&return=dashboard`                             | 게시본에서 대시보드로 돌아가기                              |

대시보드에는 최근 질문·내 질문지 각 최대 4개를 카드로 표시하고 카드 영역을 누르면 목록으로 이동한다. 별도 생성 버튼은 대시보드에 두지 않는다. 게시된 질문지는 본인과 다른 제작자의 게시본을 함께 테이블로 표시하며 제작자 이름을 포함한다. 타인이 게시한 미확인 질문지는 연한 파란 배경·파란 점·NEW로 구분하고 실제 상세 화면을 열면 확인 처리한다. 목록 조회만으로 확인 처리하지 않는다.

파일은 `app/(private)/dashboard/_views/questions/` 아래에 둔다.

| 책임                            | 위치                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| 통합 진입점·대시보드            | `QuestionsView.tsx`, `components/dashboard/`                                            |
| 독립 질문 제작·목록·미리보기    | `components/question/`, `hooks/`, `lib/`                                                |
| 질문지 제작·게시·기존 응답·알림 | `components/questionnaire/`                                                             |
| 질문지 저장·갱신                | `hooks/questionnaire/`, `lib/questionnaire/`                                            |
| HTTP 연결                       | `app/api/questions/[[...path]]/route.ts`, `app/api/questionnaires/[[...path]]/route.ts` |

이전 `_views/questionnaire/` 전체와 미사용 `PublishQuestionnaireButton`은 제거했다. 이름에 questionnaire가 있어도 위 현행 구조의 파일·API·DB는 삭제 대상이 아니다.

## 관리 목록 UI

질문 관리 대시보드·독립 질문 목록·내 질문지 목록은 학습법/탐구활동과 같은 `CollectionHeader`, `CollectionSearch`, `CollectionPagination`을 사용한다. 관리 진입 카드 두 개는 공통 `Card`의 옅은 노란 제목 영역과 흰색 본문으로 표시한다. 생성 버튼은 목록 제목 옆에 배치하고 모바일에서는 “추가”로 축약한다. 원본 질문의 Drawer를 닫을 때에는 기존 열기 버튼 또는 목록 제목으로 포커스를 돌린다.

- 표는 공통 shadcn `Table`의 회색 머리글·흰색 행·외곽 테두리를 사용한다. `CollectionTableState`는 표 머리글을 유지한 채 로딩 스켈레톤·빈 결과·오류/재시도를 표시한다. 최소 본문 높이는 18rem이며 실제 행 수·내용에 따라 표는 더 높아질 수 있다.
- 모바일 질문 표는 제목 아래에 참조/사용 배지·관리자 화면의 제작자를 모으고 삭제는 별도 관리 열에 둔다. 내 질문지 표는 질문지·상태·관리 열로 간소화하고 최근 수정일은 제목 아래로 옮긴다. 대시보드의 게시/배포 표는 제목 아래에 제작자·게시/배포일을 모으고 확인 상태/제출 수를 별도로 표시한다. 데스크톱 보조 열은 화면 폭에 따라 단계적으로 표시한다.
- 질문의 테이블/그래프 전환과 일반 컨설턴트의 제출 전/제출 완료 전환은 공통 shadcn `Tabs`를 사용한다. 그래프 내용과 관계 계산은 기존 그대로다.
- 참조/사용 표시는 무채색, 미처리 검토 수는 옅은 노랑 `Badge`로 표시한다. NEW·새 검토 요청과 미확인 행의 파란 알림 의미는 유지한다. 화면 표시만 바뀌며 읽음 기록·요청 처리 조건은 바꾸지 않는다.
- 질문 목록은 기존 서버 검색/10개 페이지를 유지한다. 질문지·대시보드 게시/배포 목록은 기존 클라이언트 검색/10개 페이지다. 이번 UI 변경은 서버 페이지네이션 전환이나 API·DB·권한 변경을 포함하지 않는다.

## 질문 제작과 목록

리드는 본인이 만든 질문만 본다. 실제 관리자는 관리자 화면에서 전체 질문과 제작자 이름을 본다. 관리자도 리드 화면으로 전환하면 서버 조회를 본인 질문으로 좁히며 제작자 열은 숨긴다. 표시 역할은 실제 DB 권한을 부여하거나 변경하지 않는다. 일반 컨설턴트와 학생에게 독립 질문 목록은 제공하지 않는다.

질문 목록은 최근 수정 순, 서버 페이지당 10개다. 관리용 이름과 질문 본문의 일반 텍스트를 검색하며 입력 후 300ms 디바운스를 적용한다. 공백을 정리한 검색어 전체의 부분 일치이며 대소문자를 구분하지 않는다. 한글 부분 검색은 가능하지만 초성·오타·형태소 검색은 아니다. `%`, `_`, 역슬래시는 문자로 검색한다. 설명·답변 열·선택지는 검색 대상이 아니다. 검색 변경 시 첫 페이지로 이동한다.

테이블은 질문, 참조 중인 질문, 사용 중인 질문지, 관리 열을 표시한다. 참조·사용 수는 각각 배지 하나와 목록 툴팁으로 표시한다. 사용·참조 중이면 삭제 버튼을 비활성화하고 툴팁으로 이유를 안내한다. 독립 질문 삭제 API는 현재 `archive_question`을 사용해 목록에서 제외하는 보관 방식이다. UI의 삭제 표현이 물리 삭제를 뜻하지는 않는다. 그래프는 관계 전체가 필요해 별도 전체 조회·클라이언트 검색을 사용한다.

질문 생성·수정은 Drawer에서 진행하고 목록 검색·페이지 상태를 유지한다. 본문은 필수, 관리용 이름은 선택이며 비어 있으면 본문 텍스트를 표시 이름으로 사용한다. 새 문서를 전혀 바꾸지 않았으면 저장 버튼은 비활성이고 바로 닫힌다. 다른 내용을 수정하면 저장 시도와 닫기 확인을 제공하지만 본문이 비어 있으면 저장 불가 이유를 안내한다. 수동·자동 저장 실패는 토스트로 표시한다. 미완성 입력은 서버에 저장하지 않으며 로컬 임시 복구와 저장 중 입력 보존을 유지한다.

답변 열은 서술형·척도형·단일선택형·다수선택형과 특수 유형인 탐구활동 참조형을 지원한다. 열·선택지 ID는 표시 순서와 별개다. 선택형은 목록/칩과 직접 입력 항목을 지원하고 직접 입력은 일반 선택지 다음에 표시한다. 신규 독립 질문에서 추가 서술은 별도 서술형 열로 구성한다. 탐구활동 열은 본인의 활성 확정 활동 하나를 UUID로 선택하며 미리보기 선택은 저장하지 않는다.

단일·반복 행과 최소/최대 행 수, 순서별 행 이름을 설정한다. 이름 설정은 테이블 UI이며 미지정 이름은 숫자다. 행 이름은 답변 식별자가 아니다. 참조형 행 수는 앞선 질문의 응답을 따른다.

조건은 공통 Select로 질문 → 특정 열/모든 열 → 조건 순서다. `응답했을 때`는 특정 열 또는 같은 행의 모든 열을 검사한다. `선택했을 때`는 직접 입력 없는 선택형 열에서만 제공하고 단일은 equals, 다수는 includes로 저장한다. 앞선 응답 참조를 켜면 일치하는 원본 행만 ID 기준으로 반복한다. 조건 변경으로 숨겨진 미리보기 답변은 다른 행의 값을 덮어쓰지 않는다.

`조건 해제` 버튼과 조건 메뉴의 `조건 없음`은 조건·응답 참조·선행 연결을 함께 해제한다. 선택 대상이 목록에 없어도 해제 버튼을 사용할 수 있다. 참조형은 단일 행 설정으로 돌아가며 일반 표·흐름표의 직접 설정한 행/시기는 유지한다. 해제한 후속 질문을 저장해야 원본의 열 구성 수정 제한이 풀린다. 다른 참조가 남아 있거나 배포 잠금이 있으면 계속 제한하며, 참조 체인은 마지막 후속 질문부터 해제한다. 이 정책상 저장 거절은 실제 revision 충돌과 구분해 같은 편집기에서 재저장할 수 있다.

설명은 질문 본문·답변과 분리된 `question_details`에 저장한다. 제목·서식 본문·공개 여부를 설정하며 미리보기에는 공개 설명만 표시한다. `save_question`이 질문과 설명을 원자적으로 저장한다. details 생략은 보존, 빈 배열은 삭제다.

## 질문지 제작

### 학습법 등록 안내 카드

새 카드 제작 화면의 `카드 종류`에서 `학습법 등록 안내`를 선택한다. 제목·안내 내용·버튼 이름(기본 `학습법 추가`)을 작성해 저장한 뒤 기존 질문 불러오기/배치 경로로 원하는 질문지와 위치에 재사용한다. 특정 주차나 질문 ID에 묶지 않는다. 저장 후 카드 종류는 고정되며 제목·본문·버튼 이름과 설명은 기존 수정·배포 잠금 규칙을 따른다.

이 카드는 답변 열·행·조건을 갖지 않는다. 버튼은 현재 사용자의 기존 학습법 등록 Drawer를 직접 열며 확정한 학습법은 학습법 관리에 저장한다. 학습법을 질문 답변으로 첨부하거나 질문지 답변 작성 상태를 바꾸지 않는다. 제출 내용 열람에서는 버튼을 비활성 표시한다. 안내 카드만 있는 질문지에는 답변 저장·제출 버튼을 표시하지 않으며, 일반 질문이 함께 있으면 그 답변의 필수 검사와 제출을 유지한다.

질문지 목록은 최근 수정 순의 테이블이며 페이지당 10개를 표시한다. 현재 질문지 목록의 검색·페이지네이션은 내려받은 목록에 대한 클라이언트 처리다. 상태 필터는 공통 Button의 다중 선택 버튼이고 보관은 기본 선택하지 않는다. 수정 중은 회색, 게시는 옅은 노랑, 배포는 검정 바탕·노란 글자, 보관은 흰색·회색 글자로 구분하며 상태명과 선택 표시를 함께 제공한다. 상태 Select도 같은 상태 토큰을 사용한다.

질문지 편집은 페이지에서 제목·섹션·질문 배치를 구성한다. `질문 추가하기`는 Drawer를 열어 새 질문 만들기/저장된 질문 불러오기 탭을 제공한다. 불러오기 카드를 눌러 원본을 열고 수정·저장 후 배치할 수 있다. 여기서 수정하면 원본 질문도 수정된다. 질문 저장과 질문지 배치 저장은 별개다.

원본 하나는 한 질문지에 한 번 배치한다. 필요한 선행·참조 질문을 먼저 배치하고 중복·순환·잘못된 순서를 검증한다. 질문·섹션 순서를 바꿀 수 있으며 배치 삭제는 원본 삭제가 아니다. 제목이 비어 있으면 저장을 막고, 변경하지 않은 새 문서는 확인 없이 닫으며 변경 후 미저장 이탈은 확인한다. 변경 시 10초 자동 저장·수동 저장을 제공하고 질문 Drawer 편집 중에는 질문지 자동 저장을 멈춘다.

제작 중 및 게시된 질문지는 원본의 최신 내용을 참조한다. 배치 시 별도 질문 객체나 불변 스냅샷을 만들지 않는다. 미리보기는 회색 배경에 흰 질문 카드로 표시하고 조건·행 참조를 평가한다. 미리보기 답변은 저장하지 않는다.

## 게시와 검토 요청

현재 상태 Select는 작성자의 수정 중↔게시를 허용하고, 게시 중인 본인 질문지는 확인 후 실제 배포한다. 확인 창에서 질문지 구성과 포함된 원본 질문·설명·답변 설정이 수정/삭제 불가가 됨을 안내한다. 같은 원본을 사용하는 다른 질문지에서도 질문 수정은 막힌다. DB가 원본 질문별 미처리 검토 요청을 재검사하며, 읽음 여부·출처 질문지와 무관하게 미처리가 있으면 배포 전체를 롤백한다. 배포 시 원본에 distribution_locked_at을 설정하고 원본·설명 변경을 DB 트리거로 차단한다. 배포본 구성은 기존 불변성 트리거로 보호한다. 작성자와 관리자는 보관 메뉴로 질문지를 숨길 수 있다. 보관 시 컨설턴트의 목록·상세 조회와 응답 저장이 차단되며, 질문지 내용·기존 응답·배포 원본 잠금은 유지한다. 작성자는 내 질문지 목록의 보관 필터에서 보관 전 상태로 복원할 수 있다. 배포본을 복원하면 컨설턴트에게 다시 표시된다. 배포본은 저장된 응답이 없으면 작성자가 같은 ID로 게시 또는 수정 중으로 되돌릴 수 있다. 임시저장도 응답으로 보호하며, 단순 열람의 빈 세션은 되돌리기를 막지 않는다. 게시 가이드 응답은 이 판정에서 제외하고 보존한다. 되돌리면 컨설턴트 목록에서 사라지며 다른 배포본에서 쓰지 않는 원본만 잠금을 해제한다. 기존 배포본에서 수정용 복사본을 만들던 동작은 이 복귀 동작으로 대체한다.

컨설턴트는 배포 목록과 상세에서 질문과 공개 설명을 열람한다. 비공개 설명과 독립 원본 질문 조회 권한은 제공하지 않는다. 새 배치형 배포본은 답변 입력과 저장·제출을 제공한다. 저장(자동 저장 포함)은 본인 전용이며 제출하면 리드·관리자에게 공개된다. 제출 후에도 수정할 수 있고 저장만 하면 마지막 제출 내용이 유지되며 재제출할 때 공개 내용이 갱신된다. 리드·관리자는 대시보드의 배포된 질문지에서 제출된 답변을 조회한다. 단순 열람은 빈 세션만 만들며 저장 이력으로 취급하지 않는다. 이 기능의 migration `20261002074415_distributed_response_submissions.sql`은 로컬 적용 완료, 운영 적용 대기다. 기존 구형 배포본 응답 기능은 유지한다. 질문 복사 제작 기능은 후속 범위다.

게시하면 다른 리드·관리자에게 공개한다. 작성자는 편집 화면을 사용하고, 다른 사람은 별도 미리보기 탭 없이 실제 질문지 형태로 본다. 게시본의 돌아가기는 대시보드로 연결한다. 원본 질문은 다른 사람의 독립 질문 목록에 추가하지 않고, 해당 게시본에 배치된 원본만 전용 RPC로 조회한다. 제작자 이름도 게시된 미보관 질문지 범위에서 조회한다.

로컬에서는 질문지 전용 설명 API·테이블을 제거하고 원본 질문 편집기로 설명을 관리한다. 수정 권한은 원본 질문의 작성자/관리자 정책을 따른다. 다른 리드는 게시본에서 검토 요청만 추가한다. 운영은 아직 이전 설명 구조를 유지하므로 로컬 정리 migration을 그대로 배포하지 않는다.

검토 요청의 등록·작성자 확인·이전 요청 보존 코드는 있으나 **게시 후 사용자 점검은 아직 하지 않았다.** 설명 권한에 대한 자동 검증과 이 상태를 혼동하지 않는다. 후속 점검에서는 타인 요청 등록, 작성자 알림/확인, 확인 후 이력 보존, 새로고침·재접속 반영을 확인한다.

## 가이드 응답

지정 가이드 계정은 게시본에서 실제 응답을 저장하고 다른 리드는 저장 없는 미리보기를 사용한다. 가이드 답변은 질문 미리보기의 설명 아래 접힘 영역에 표시하며 서식과 행 이름을 유지한다.

최신 게시본의 제목·섹션·질문·순서를 조회하고, 5초 간격 및 포커스 복귀 시 갱신한다. 남아 있는 동일 ID·유형의 미저장 입력은 보존한다. 완료 상태에서도 가이드 답변은 수정할 수 있다.

질문 본문 수정·답변 항목 추가는 기존 답변을 유지한다. 가이드 답변이 있는 항목을 삭제하거나 유형을 바꾸면 먼저 확인하고 해당 답변만 삭제한다. 질문·섹션 제거도 가이드 답변이 있으면 확인하며 해당 질문지의 응답만 삭제한다. 다른 질문지의 응답은 유지한다. 제거 후 다시 배치한 질문은 빈 응답으로 시작한다. 이전 답변 보관·복구나 구조 변경 재작성 안내는 제공하지 않는다.

## 리치 텍스트 탐구활동 명령어 (2026-10-01)

모든 공통 리치 텍스트 입력에서 `@` 또는 `@탐구활동`을 입력하면 명령어 메뉴가 표시된다. `탐구활동 참조 권장`과 무관하며 권장 옵션은 기존 파란 안내만 제어한다. 클릭 또는 방향키/Enter로 선택하고 Escape로 닫는다. 선택하면 입력창 위에 본인 탐구활동 목록·검색과 `탐구활동 추가` 버튼을 표시한다. 추가는 기존 작성 Drawer를 열며 임시저장/확정 기능을 재사용한다. 확정 활동만 답변에 첨부할 수 있고 임시저장 활동은 작성 후 확정해야 한다.

첨부한 활동은 RichText의 `explorationReference` mark에 UUID를, text에 활동명을 저장한다. 기존 text 노드와 저장/자동 저장 경로를 사용하므로 DB migration은 없다. 본문 추출 시 활동명이 유지되며 열람 화면에서는 활동명을 눌러 기존 조회 권한 범위 안에서 상세를 연다. 삭제되거나 권한이 없는 활동은 안내를 표시하고 저장된 활동명은 유지한다. 원본 활동 수정은 저장된 표시 이름을 자동 변경하지 않는다. 새 배치형 배포는 활성화하지 않는다.

검증: 타입 검사, 변경 파일 린트, RichText/질문지 저장 회귀 22개, 예시 데이터를 사용한 브라우저 명령어·첨부·새 작성 Drawer 확인. 실제 로그인 계정의 저장/재조회 실사용 검증은 아직 하지 않았다.


첨부 목록 UI 보완: 입력 위에 겹쳐 뜨는 Portal 팝업을 사용하며 주변 레이아웃을 밀지 않는다. 카드에는 주제·학년·학기·기재 영역만 표시하고 카드 전체 클릭으로 첨부한다. hover/키보드 focus 시 `첨부하기` 문구를 보여준다. `탐구활동 추가`는 목록 마지막 항목이며 목록 제목은 제거했다. 명령어에 아이콘·짧은 설명을 추가하고 팝업과 참조 권장 말풍선에 X 닫기를 제공한다. 사용자 요청에 따라 이번 수정에는 브라우저 테스트를 실행하지 않았다.

### 질문 검토 요청 (2026-10-02)

검토 요청은 질문지 배치가 아닌 원본 질문에 귀속한다. 같은 질문의 요청은 여러 질문지·질문 편집 화면에서 공유한다. 게시된 질문에는 리드/관리자가 요청을 작성하고 원본 질문 작성자 또는 관리자가 처리 완료한다. 가이드 답변 작성 권한과 별개다. 완료 내역은 접어 표시하고 질문 수정으로 자동 처리하지 않는다. 질문 목록에 미처리 개수를 표시한다. 운영 적용과 DB 계약은 questions-operations.md의 최신 절을 따른다.

검토 요청의 미확인 여부는 question_review_reads로 제작자별 관리한다. 목록·대시보드에 파란 새 요청 표시가 나오며 요청 카드가 실제 화면에 표시되면 해제한다. 처리 완료와 읽음은 구분한다.

최신 정책(2026-10-02): 검토 요청 본인 작성 차단과 새 알림 수신자는 질문지 제작자가 아닌 원본 질문 제작자다. 일반 리드는 본인 질문만 조회·배치하므로 통상 동일하지만 관리자는 타인의 질문도 배치할 수 있다. 게시된 질문지의 타인 질문 공유 조회는 독립 질문 관리 접근 권한과 구분한다.

리드·관리자 대시보드는 게시된 질문지 아래에 배포된 질문지 테이블을 표시한다. 제목 검색·10개 페이지·배포일·제출된 응답 수를 제공한다. 제출 수는 임시 저장을 제외한 응답자별 마지막 제출본 개수이며 재제출은 중복 집계하지 않는다. 집계 RPC는 리드·관리자만 실행한다. Migration: `20261002081911_distributed_submission_counts.sql` (로컬 적용, 운영 사용자 적용 대기).

- 진로 흐름 부분 제출(2026-10-02): 원본 `5f6064ad-1dd6-4e0d-95dd-611ccacbce92`는 활성 칸 하나의 유효 응답만으로 배포 답변 제출을 허용한다. 전체 공백은 거절하며 다른 질문의 모든 필드/최소 행 검사는 유지한다. `20261002083415_career_flow_partial_submission.sql` 로컬 적용·한 칸/빈 답변 롤백 검증·기존 배포 응답 회귀·보안 검사 통과. 운영은 사용자 적용 대기. 실제 브라우저 제출은 수행하지 않았다.

## 표형 응답 제작 (2026-10-11)

일반 표의 선택 열은 옅은 회청색 머리글·셀 배경과 `(선택)` 배지로 구분해 필수 항목보다 강조를 낮춘다. 긴 셀 placeholder는 한 줄 말줄임으로 칸 안에 표시하고 실제 답변은 계속 줄바꿈·높이 확장을 허용한다. 응답 화면에는 최소 작성 수와 최대 행 수 안내를 표시하지 않으며, 반복 답변의 추가 버튼에도 현재/최대 수치를 표시하지 않는다. 제작 설정과 실제 행 추가·삭제·제출 제한은 유지한다.

독립 질문과 질문지의 공통 질문 제작 화면에서 답변 표시 방식을 카드·일반 표·흐름표로 선택한다. 기존 질문의 기본은 카드이며 기존 질문지를 자동으로 바꾸지 않는다. 일반 표는 답변 열 제목을 가로 머리글로 표시하고 셀에서 바로 입력한다. 제작자는 열별 필수 입력, 최소 작성 행 수, 처음 표시할 행 수, 최대 행 수(20 이하)를 지정한다. 최소 작성 행 수가 5이면 응답 화면에도 적어도 5행을 표시한다. 초기 표시 행 수가 최소보다 크면 남는 빈 행은 작성 필수가 아니다. 응답자는 최대 이하에서 행을 추가하고 최소를 유지하는 범위에서 삭제할 수 있다. 답변이 있는 행을 삭제할 때 확인한다.

흐름표는 행 이름을 가로의 시기 머리글로, 답변 열을 세로의 답변 항목으로 표시한다. 기본 시기의 이름과 개수는 제작자가 설정하고 응답자는 기본 시기를 삭제하지 않는다. 제작자가 허용한 위치에는 아래 중간 시기 추가 기능을 사용할 수 있다. 모든 기본 시기를 표시하되 최소 작성 시기 수만큼 한 칸 이상 작성하면 제출할 수 있다. 각 시기의 모든 칸을 채우지는 않아도 된다. 앞선 응답의 행을 참조하는 구성에는 일반 표를 사용할 수 있고, 시기를 고정하는 흐름표는 선택하지 않는다.

서술형은 기존 서식·`@탐구활동`·`@학습법` 입력을 사용한다. 일반 표·흐름표의 단일선택형·다수선택형은 셀 안의 드롭다운으로 표시하며 선택 해제와 직접 입력 항목을 지원한다. 다수선택형의 기존 직접 입력 답변 여러 개는 다른 선택지를 추가·해제해도 내용과 ID를 유지한다. 제작자는 답변 유형을 선택형으로 바꾸고 선택지를 설정한다. 카드에서는 기존 목록·칩 설정을 유지한다. 선택형·척도형·참조형은 기존 값 형식을 유지하며 드롭다운 표시에는 별도 DB 변경이 없다. 표는 가로 스크롤과 머리글 고정을 제공한다. 열 제목·시기 이름만 고쳐 다른 추천 목록이나 성적 흐름표를 만들 수 있다. 특정 질문 ID에 연결된 기존 진로 흐름 화면은 기본 카드 설정에서 기존 동작을 유지한다.

설정은 `questions.answer_layout`(`cards`/`table`/`flow`), `initial_rows`와 기존 `min_rows`·`max_rows`·`row_labels`에 저장한다. API 문서는 `answerLayout`·`initialRows`를 사용하고 열별 필수 여부는 `fields[].required`(생략 시 필수)로 저장한다. 표시 전환만으로 기존 필드·응답 행 ID를 바꾸지 않는다. 빈 기본 행을 표시하는 초기화는 자동 저장하지 않는다. 표·흐름표는 빈 행을 활성 답변에서 제외하고 최소 작성 행/시기 수를 서버에서 검사한다. 작성된 일반 표 행은 필수 열을 채워야 하며 선택 열과 흐름표의 입력된 값도 유형 검증을 거친다. 제출된 흐름표는 빈 시기의 자리와 원래 ID를 유지하며 조건상 비활성 입력은 빈 자리로 대체해 공개하지 않는다.

Migration: `20261011143258_question_answer_layouts.sql`. 앱 타입·변경 파일 린트·표 설정/행 표시·기존 행 참조·입력 보존·RichText·배포 응답 폼 JS 회귀 29개·Webpack 빌드 통과. 2026-10-12 사용자의 승인에 따라 에이전트가 운영 함수 치환 기준 10개와 외부 웹훅 부재를 확인하고, 임시 migration과 신규 `question_answer_layouts.sql` 회귀를 한 트랜잭션으로 시험·롤백한 뒤 이 migration 한 개를 영구 적용했다. 적용 후 신규 SQL 회귀와 기존 배포·게시·조건 응답 SQL 3개, 대기 없음 확인도 통과했으며 운영 가이드 함수는 보존했다. 보안 advisor는 기존 경고 4개로 동일하고 새 경고는 없다. 로컬 DB 엔진이 없어 로컬 migration 적용·SQL 회귀는 미실행이다. 실제 브라우저 검증과 앱 배포 확인은 하지 않았다. 적용 기록과 앱 배포·기능 확인 순서는 [운영 안내](questions-operations.md#표형-응답-제작-2026-10-11)를 따른다.

### 흐름표의 중간 시기 추가 (2026-10-13)

제작자는 `시기 이름 설정`의 `시기 추가 허용`에서 어느 기본 시기 다음에 응답자가 시기를 추가할 수 있는지 정한다. 응답자는 시기 사이의 좁은 추가 칸에서 + 버튼을 눌러 새 시기를 넣고 이름을 직접 입력한다. 추가 칸은 폭 48px의 옅은 회청색 셀 한 개로 시기 머리글과 모든 답변 행을 세로로 합치며, 이미 추가한 시기들이 있으면 그 뒤와 다음 기본 시기 사이에 표시한다. 기본 시기와 추가 시기를 합쳐 최대 20개까지 작성하며, 기본 시기가 20개이면 추가를 허용할 수 없다. 추가한 시기는 이름 수정·삭제가 가능하고 답변이 있으면 삭제 전에 확인한다. 기본 시기의 순서·ID와 기존 답변은 추가·삭제로 바뀌지 않는다.

추가 위치는 API의 `flowInsertAfter`와 DB의 `questions.flow_insert_after`에 기본 시기의 1부터 시작하는 번호 배열로 저장한다. `maxRows`는 기본 시기 수로 유지하며, 단일 행 흐름표도 기본 시기 1개 뒤에 추가할 수 있다. 추가 시기의 이름은 최대 100자이고 임시 저장에서는 비워 둘 수 있지만, 답변을 작성한 추가 시기는 제출 전에 이름이 필요하다. 이름만 입력한 시기는 최소 작성 수에 포함하지 않는다. 저장·재열기·제출 내용·가이드 답변에서도 추가 시기의 위치와 이름을 유지한다.

제작자가 추가 허용을 해제해도 이미 저장된 추가 시기는 편집·삭제할 수 있으며 그 위치에 새 시기를 넣는 것은 차단한다. 기존 시기 정보를 저장한 원본은 기본 시기 수와 표시 방식을 바꾸지 못한다. 구형 편집기의 흐름표 내용 수정 요청에서 `flowInsertAfter`가 생략되면 기존 설정을 보존하고, 명시적 빈 배열은 허용 위치를 해제한다. 조건으로 흐름표 전체가 비활성이면 제출본에는 자리 정보만 남기며 추가 시기의 이름과 답변은 공개하지 않는다. Migration은 `20261013033907_question_flow_insertions.sql`, SQL 회귀는 `supabase/tests/question_flow_insertions.sql`이며 적용·검증 결과는 운영 안내에 기록한다.

아직 저장되지 않은 흐름표와 다른 제작자의 기본 시기 수/표 형식 변경이 충돌하면, 응답 화면은 현재 구성과 입력을 유지하고 저장을 중단한다. 안내에 따라 현재 입력을 복사한 뒤 질문지를 다시 열어 최신 구성을 사용한다. 같은 시기 수에서 이름·내용·추가 허용 위치만 바뀌는 경우에는 기존 입력을 유지하면서 최신 구성으로 계속 작성한다.


### 배포본 검토 요청 공유 (2026-10-12)

다른 컨설턴트 리드도 활성 배포 질문지에 포함된 질문의 검토 요청 전체를 읽을 수 있다. 조회 허용만 확장하며 배포본에서 새 요청 작성은 허용하지 않는다. 원본 작성자·기존 요청자·관리자의 기존 조회 범위는 유지한다.

### 제출 응답 PDF 다운로드

배포 질문지의 제출 응답 목록에서 `사람별 PDF 일괄 다운로드`를 누르면 현재 목록의 마지막 제출본을 사람마다 PDF 한 개로 만들어 ZIP으로 내려받는다. 사람별 답변 상세에서는 `PDF 다운로드`로 한 사람의 제출본을 받을 수 있다. 생성 중 진행 수와 실패 시 재시도 안내를 표시한다.

PDF에는 질문지 제목, 응답자명, 한국 시간 기준 제출일, 섹션·질문 순서와 활성 답변 행만 포함한다. 일반 표·흐름표는 긴 답변을 읽기 쉽도록 행/시기별 세로 목록으로 변환하며 기본·추가 시기 이름, 선택지명, 여러 직접 입력, 척도 점수, 서술형 강조·목록을 보존한다. 안내 카드는 응답 대상에서 제외한다. 탐구활동·학습법 참조 필드는 첨부 여부를 표시하고 상세 내용은 서비스에서 확인한다. ZIP 내부 파일명은 순번·응답자명·질문지 제목으로 구성해 동명이인도 덮어쓰지 않는다.

기존 제출 조회 API가 반환한 데이터만 사용하고 PDF 생성은 다운로드 시 브라우저에서 수행한다. API·DB 권한/스키마 변경이나 migration은 없다. 실제 브라우저 테스트 없이 `scripts/verify-submitted-response-export.mjs`, 타입 검사, 변경 파일 린트, Webpack 빌드와 가상 응답 PDF 생성·페이지 이미지 검사를 수행했다. 앱 배포 후 사용 가능하다.

### 게시 질문지에서 다른 작성자 원본 편집 조회

질문지의 원본 편집기는 게시 공동 편집 시 `questionnaireId`를 단건 질문 조회에 전달한다. 서버는 기존 `read_published_question_sources`로 질문지 접근 권한과 실제 배치를 확인하고 해당 원본만 반환한다. 관리자의 리드 화면에서도 독립 질문 목록의 작성자 필터 때문에 타인 원본이 404로 처리되지 않는다. 독립 질문 조회·목록의 기존 필터, 원본 저장 권한·배포 잠금은 유지한다. DB migration은 없고 앱 배포가 필요하다.
