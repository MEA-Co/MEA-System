# 질문·질문지 관리

## 질문지 ID 이름 통일 (2026-10-02, 최신 계약)

`20261002061031_canonical_questionnaire_identifiers.sql` 로컬 적용. 앱 타입·컴포넌트·URL 요청 본문·RPC에서 질문지는 `questionnaireId`/`questionnaire_id` 하나로 식별한다. `p_questionnaire_id`, `origin_questionnaire_id`, `p_origin_questionnaire_id`로 인자와 연결 열도 통일했다. 기존 UUID 값과 URL 경로는 유지한다. 문서의 중복 부모 ID와 내부 `questionnaire_owners` 호환 뷰는 제거했다. 배포 취소 시 초안을 복제하던 UI 분기도 제거했다.

`legacy_parent_id`와 `owner_created_at`은 기존 데이터 추적을 위한 보존 열이며 앱/RPC는 조회·식별에 사용하지 않는다. 과거 이전 장부의 부모 ID도 `legacy_target_parent_id`로 보존했다. 과거 migration 파일은 이력 재현용으로 유지한다. `question_versions` 및 `question_version_id`는 질문 응답 정의를 보존하며, 응답 JSON에서는 `questionVersionId`로 명확히 구분한다. `revision`은 동시 수정 충돌 방지에 계속 사용한다.

이 변경은 이전 앱과의 이름 호환을 의도적으로 종료한다. 배포 시 저장을 마친 뒤 DB migration → 새 앱 배포 → 기존 탭 새로고침 순서를 따른다. 운영 적용은 `questions-operations.md` 마지막 절을 참고한다.


현재 구현 기준: 2026-09-29. 로컬의 원본 참조 필수 저장 변경은 [운영 안내의 로컬 전용 단계](questions-operations.md#원본-참조-저장-통일--로컬-전용-단계-2026-09-29)를 따른다. 운영 적용 전 기존 게시본의 동일 ID 전환이 필요하다. **질문 제작·질문지 제작·게시까지 구현했으며, 게시 후 검토 요청 흐름은 사용자가 아직 점검하지 않았다.** 코드의 자동 검증과 사용자 점검 완료를 구분한다. 새 배치형 질문지의 배포·실제 응답 저장은 후속 작업이다.

## 서술형 탐구활동 참조 권장

각 서술형 답변 열의 설정에 `탐구활동 참조 권장` 체크박스를 둔다. 기본은 해제이며 체크/해제를 저장·재조회할 수 있다. 옵션을 켜면 질문 및 질문지 미리보기의 해당 답변 입력에 포커스하면 파란 테두리와 파란 말풍선을 표시한다. 말풍선은 `탐구활동 참조가 필요한 질문입니다.`와 `@탐구활동 을 입력하여 탐구활동을 언급하며 답변해주세요!` 두 줄이며 포커스를 벗어나면 숨긴다. 다른 답변 유형으로 바꾸면 옵션을 제거한다. 권장 안내이며 탐구활동 첨부를 필수로 요구하지 않는다.

설정은 기존 `questions.fields` JSONB의 `explorationRecommended` boolean으로 저장한다. API 스키마와 DB 검증 함수가 서술형에만 허용한다. 기존 필드에 속성이 없으면 해제로 해석하며 데이터 일괄 변경은 하지 않는다. 로컬 migration `20261001034040_question_text_exploration_recommendation.sql`, 운영 순서는 `questions-operations.md`의 같은 날짜 절을 따른다.

## 진입점과 파일 구조

대시보드 페이지 키는 `questions` 하나다. 이전 `view=questionnaire` 접근 항목·별도 렌더러·아이콘·호환 분기는 제거했다. 이전 URL은 다른 미지원 view와 같이 역할별 기본 화면으로 처리한다. `questionnaires` 탭 값과 `/api/questionnaires`는 현행 질문지 기능이므로 유지한다.

| URL (`/dashboard` 기준)                                       | 화면                                                        |
| ------------------------------------------------------------- | ----------------------------------------------------------- |
| `?view=questions`                                             | 리드·관리자: 질문 관리 대시보드. 컨설턴트: 기존 배포본 목록 |
| `?view=questions&tab=questions`                               | 질문 목록                                                   |
| `?view=questions&question=<ID 또는 new>`                      | 질문 생성·수정 Drawer                                       |
| `?view=questions&tab=questionnaires`                          | 내 질문지 목록                                              |
| `?view=questions&tab=questionnaires&draft=<버전 ID 또는 new>` | 질문지 편집·조회                                            |
| 위 상세 URL에 `&return=dashboard`                             | 게시본에서 대시보드로 돌아가기                              |

대시보드에는 최근 질문·내 질문지 각 최대 4개를 카드로 표시하고 카드 영역을 누르면 목록으로 이동한다. 별도 생성 버튼은 대시보드에 두지 않는다. 게시된 질문지는 본인과 다른 제작자의 게시본을 함께 테이블로 표시하며 제작자 이름을 포함한다. 타인이 게시한 미확인 질문지는 연한 파란 배경·파란 점·NEW로 구분하고 실제 상세 화면을 열면 확인 처리한다. 목록 조회만으로 확인 처리하지 않는다.

파일은 `app/(private)/dashboard/_views/questions/` 아래에 둔다.

| 책임                            | 위치                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| 통합 진입점·대시보드            | `QuestionsView.tsx`, `components/dashboard/`                                            |
| 독립 질문 제작·목록·미리보기    | `components/question/`, `hooks/`, `lib/`                                                |
| 질문지 제작·게시·기존 응답·알림 | `components/questionnaire/`                                                             |
| 질문지 저장·갱신                | `hooks/questionnaire/`, `lib/questionnaire/`                                            |
| HTTP 연결                       | `app/api/questions/[[...path]]/route.ts`, `app/api/questionnaires/[[...path]]/route.ts` |

이전 `_views/questionnaire/` 전체와 미사용 `PublishQuestionnaireButton`은 제거했다. 이름에 questionnaire가 있어도 위 현행 구조의 파일·API·DB는 삭제 대상이 아니다.

## 질문 제작과 목록

리드는 본인이 만든 질문만 본다. 실제 관리자는 관리자 화면에서 전체 질문과 제작자 이름을 본다. 관리자도 리드 화면으로 전환하면 서버 조회를 본인 질문으로 좁히며 제작자 열은 숨긴다. 표시 역할은 실제 DB 권한을 부여하거나 변경하지 않는다. 일반 컨설턴트와 학생에게 독립 질문 목록은 제공하지 않는다.

질문 목록은 최근 수정 순, 서버 페이지당 10개다. 관리용 이름과 질문 본문의 일반 텍스트를 검색하며 입력 후 300ms 디바운스를 적용한다. 공백을 정리한 검색어 전체의 부분 일치이며 대소문자를 구분하지 않는다. 한글 부분 검색은 가능하지만 초성·오타·형태소 검색은 아니다. `%`, `_`, 역슬래시는 문자로 검색한다. 설명·답변 열·선택지는 검색 대상이 아니다. 검색 변경 시 첫 페이지로 이동한다.

테이블은 질문, 참조 중인 질문, 사용 중인 질문지, 관리 열을 표시한다. 참조·사용 수는 각각 배지 하나와 목록 툴팁으로 표시한다. 사용·참조 중이면 삭제 버튼을 비활성화하고 툴팁으로 이유를 안내한다. 독립 질문 삭제 API는 현재 `archive_question`을 사용해 목록에서 제외하는 보관 방식이다. UI의 삭제 표현이 물리 삭제를 뜻하지는 않는다. 그래프는 관계 전체가 필요해 별도 전체 조회·클라이언트 검색을 사용한다.

질문 생성·수정은 Drawer에서 진행하고 목록 검색·페이지 상태를 유지한다. 본문은 필수, 관리용 이름은 선택이며 비어 있으면 본문 텍스트를 표시 이름으로 사용한다. 새 문서를 전혀 바꾸지 않았으면 저장 버튼은 비활성이고 바로 닫힌다. 다른 내용을 수정하면 저장 시도와 닫기 확인을 제공하지만 본문이 비어 있으면 저장 불가 이유를 안내한다. 수동·자동 저장 실패는 토스트로 표시한다. 미완성 입력은 서버에 저장하지 않으며 로컬 임시 복구와 저장 중 입력 보존을 유지한다.

답변 열은 서술형·척도형·단일선택형·다수선택형과 특수 유형인 탐구활동 참조형을 지원한다. 열·선택지 ID는 표시 순서와 별개다. 선택형은 목록/칩과 직접 입력 항목을 지원하고 직접 입력은 일반 선택지 다음에 표시한다. 신규 독립 질문에서 추가 서술은 별도 서술형 열로 구성한다. 탐구활동 열은 본인의 활성 확정 활동 하나를 UUID로 선택하며 미리보기 선택은 저장하지 않는다.

단일·반복 행과 최소/최대 행 수, 순서별 행 이름을 설정한다. 이름 설정은 테이블 UI이며 미지정 이름은 숫자다. 행 이름은 답변 식별자가 아니다. 참조형 행 수는 앞선 질문의 응답을 따른다.

조건은 공통 Select로 질문 → 특정 열/모든 열 → 조건 순서다. `응답했을 때`는 특정 열 또는 같은 행의 모든 열을 검사한다. `선택했을 때`는 직접 입력 없는 선택형 열에서만 제공하고 단일은 equals, 다수는 includes로 저장한다. 앞선 응답 참조를 켜면 일치하는 원본 행만 ID 기준으로 반복한다. 조건 변경으로 숨겨진 미리보기 답변은 다른 행의 값을 덮어쓰지 않는다.

설명은 질문 본문·답변과 분리된 `question_details`에 저장한다. 제목·서식 본문·공개 여부를 설정하며 미리보기에는 공개 설명만 표시한다. `save_question`이 질문과 설명을 원자적으로 저장한다. details 생략은 보존, 빈 배열은 삭제다.

## 질문지 제작

질문지 목록은 최근 수정 순의 테이블이며 페이지당 10개를 표시한다. 현재 질문지 목록의 검색·페이지네이션은 내려받은 목록에 대한 클라이언트 처리다. 상태 필터는 색상 칩이고 보관은 기본 선택하지 않는다. 상태 Select도 같은 상태 색상을 사용한다.

질문지 편집은 페이지에서 제목·섹션·질문 배치를 구성한다. `질문 추가하기`는 Drawer를 열어 새 질문 만들기/저장된 질문 불러오기 탭을 제공한다. 불러오기 카드를 눌러 원본을 열고 수정·저장 후 배치할 수 있다. 여기서 수정하면 원본 질문도 수정된다. 질문 저장과 질문지 배치 저장은 별개다.

원본 하나는 한 질문지에 한 번 배치한다. 필요한 선행·참조 질문을 먼저 배치하고 중복·순환·잘못된 순서를 검증한다. 질문·섹션 순서를 바꿀 수 있으며 배치 삭제는 원본 삭제가 아니다. 제목이 비어 있으면 저장을 막고, 변경하지 않은 새 문서는 확인 없이 닫으며 변경 후 미저장 이탈은 확인한다. 변경 시 10초 자동 저장·수동 저장을 제공하고 질문 Drawer 편집 중에는 질문지 자동 저장을 멈춘다.

제작 중 및 게시된 질문지는 원본의 최신 내용을 참조한다. 배치 시 별도 질문 객체나 불변 스냅샷을 만들지 않는다. 미리보기는 회색 배경에 흰 질문 카드로 표시하고 조건·행 참조를 평가한다. 미리보기 답변은 저장하지 않는다.

## 게시와 검토 요청

현재 상태 Select는 작성자의 수정 중↔게시를 허용하고, 게시 중인 본인 질문지는 확인 후 실제 배포한다. 확인 창에서 질문지 구성과 포함된 원본 질문·설명·답변 설정이 수정/삭제 불가가 됨을 안내한다. 같은 원본을 사용하는 다른 질문지에서도 질문 수정은 막힌다. DB가 원본 질문별 미처리 검토 요청을 재검사하며, 읽음 여부·출처 질문지와 무관하게 미처리가 있으면 배포 전체를 롤백한다. 배포 시 원본에 distribution_locked_at을 설정하고 원본·설명 변경을 DB 트리거로 차단한다. 배포본 구성은 기존 불변성 트리거로 보호한다. 보관 메뉴는 비활성 유지한다. 배포본은 저장된 응답이 없으면 작성자가 같은 ID로 게시 또는 수정 중으로 되돌릴 수 있다. 임시저장도 응답으로 보호하며, 단순 열람의 빈 세션은 되돌리기를 막지 않는다. 게시 가이드 응답은 이 판정에서 제외하고 보존한다. 되돌리면 컨설턴트 목록에서 사라지며 다른 배포본에서 쓰지 않는 원본만 잠금을 해제한다. 기존 배포본에서 수정용 복사본을 만들던 동작은 이 복귀 동작으로 대체한다.

컨설턴트는 배포 목록과 상세에서 질문과 공개 설명을 열람한다. 비공개 설명과 독립 원본 질문 조회 권한은 제공하지 않는다. 새 배치형 배포본의 답변 작성·저장은 아직 연결하지 않아 열람 전용으로 표시하며 응답 세션을 자동 생성하지 않는다. 기존 구형 배포본 응답 기능은 유지한다. 질문 복사 제작 기능은 후속 범위다.

게시하면 다른 리드·관리자에게 공개한다. 작성자는 편집 화면을 사용하고, 다른 사람은 별도 미리보기 탭 없이 실제 질문지 형태로 본다. 게시본의 돌아가기는 대시보드로 연결한다. 원본 질문은 다른 사람의 독립 질문 목록에 추가하지 않고, 해당 게시본에 배치된 원본만 전용 RPC로 조회한다. 제작자 이름도 게시된 미보관 질문지 범위에서 조회한다.

## 게시본 최신 구성 동기화 (2026-10-01)

### 질문 검토 요청 (2026-10-02)

검토 요청은 질문지 배치가 아닌 원본 질문에 귀속한다. 같은 질문의 요청은 여러 질문지·질문 편집 화면에서 공유한다. 게시된 질문에는 리드/관리자가 요청을 작성하고 원본 질문 작성자 또는 관리자가 처리 완료한다. 가이드 답변 작성 권한과 별개다. 완료 내역은 접어 표시하고 질문 수정으로 자동 처리하지 않는다. 질문 목록에 미처리 개수를 표시한다. 운영 적용과 DB 계약은 questions-operations.md의 최신 절을 따른다.

검토 요청의 미확인 여부는 question_review_reads로 제작자별 관리한다. 목록·대시보드에 파란 새 요청 표시가 나오며 요청 카드가 실제 화면에 표시되면 해제한다. 처리 완료와 읽음은 구분한다.

최신 정책(2026-10-02): 검토 요청 본인 작성 차단과 새 알림 수신자는 질문지 제작자가 아닌 원본 질문 제작자다. 일반 리드는 본인 질문만 조회·배치하므로 통상 동일하지만 관리자는 타인의 질문도 배치할 수 있다. 게시된 질문지의 타인 질문 공유 조회는 독립 질문 관리 접근 권한과 구분한다.


## 질문지 본체·버전 통합 (2026-10-02, 아래 과거 구조 설명보다 우선)

`20261002055633_merge_questionnaire_tables.sql`을 로컬 적용했다. 질문지는 `public.questionnaires` 한 행에 제목·상태·제작자·구성의 기준 ID·revision·게시/배포/보관 시각을 저장한다. `questionnaire_versions` 테이블과 `version_number`는 제거했다. `revision`은 저장 충돌 방지 번호이며 별도 질문지 버전을 만들지 않는다. 질문 응답 정의 보존용 `question_versions`는 이번 통합 대상이 아니다.

기존 버전 행의 ID를 새 `questionnaires.id`로 그대로 사용하여 섹션·질문 배치·응답·검토·읽음 연결을 보존한다. 과거 부모 ID는 `legacy_parent_id`, 과거 부모 생성 시각은 `owner_created_at`으로 보존한다. 기존 API의 `versionId`/`questionnaireId`, 하위 테이블의 `version_id`/`origin_version_id` 이름은 호환용으로 유지한다. 이 명칭이 질문지 버전 분리를 의미하지 않는다. `private.questionnaire_owners`는 한 테이블을 읽는 내부 호환 뷰이며 추가 데이터를 저장하지 않는다.

migration은 부모별 정확히 1개·번호 1인 경우에만 진행하고, 잠금 및 전체 원본 필드 비교 후 중복 부모 테이블을 제거한다. 예상치 못한 다중 버전·의존성·데이터 차이가 있으면 트랜잭션 전체가 중단된다. 운영 적용은 `questions-operations.md` 마지막 절을 따른다.
