# 질문지 게시 활성화

작성자는 질문지 목록의 상태 Select에서 `수정 중 → 게시`로 변경할 수 있다. 게시된 질문지는 다른 컨설턴트 리드·관리자의 질문 관리 대시보드에 표시된다. 일반 컨설턴트에게는 배포 전까지 노출하지 않는다. 배포·보관 선택지는 비활성 상태를 유지한다.

독립 질문 목록은 계속 작성자 전용이다. `read_published_question_sources`는 실제 인증 역할과 질문지의 게시 상태·미보관 상태를 확인하고 해당 질문지에 배치된 원본만 반환한다. 다른 리드의 상세 화면은 이 전용 결과로 실제 질문지 형태를 바로 표시하며 원본 편집 링크를 제공하지 않는다. 수정 중으로 돌리면 전용 조회도 다시 차단된다. 별도 스냅샷을 만들지는 않으며 게시된 질문지는 원본의 최신 내용을 표시한다.

## 운영 적용 순서

1. 기존 migration 이력과 적용 대상을 확인한다.

```bash
npx supabase migration list --linked
npx supabase db push --linked --dry-run
```

신규 파일은 `20260929063207_questionnaire_published_sources.sql`과 `20260929071720_questionnaire_published_review_permissions.sql`이다. 이미 적용한 파일은 제외한다. 기존 이력이 일치하고 해당 파일들만 대기 중이면 다음 단계로 진행한다. 이전 migration도 대기 중이면 각 변경의 운영 적용 여부를 먼저 검토한다. `docs/local-supabase.md`의 이력 정리 주의사항을 따른다.

2. DB 적용 후 이력을 확인한다.

```bash
npx supabase db push --linked
npx supabase migration list --linked
```

3. 앱을 배포한다.
4. 작성자 계정에서 질문지를 게시한다. 다른 리드 계정에서 대시보드에 표시되는지, 질문지 화면에서 질문 본문·답변 열·행 설정·설명이 보이는지 확인한다. 그 리드의 독립 질문 목록에는 원본이 추가되지 않아야 한다.

로컬 검증: `supabase/tests/questionnaire_published_sources.sql`. 새로 만든 리드·다른 리드·컨설턴트로 게시/조회/수정 권한과 게시 취소 후 접근 차단을 확인하며 테스트 데이터는 롤백한다.

게시 목록에는 제작자 이름을 표시한다. 게시본에서 돌아가기는 질문 관리 대시보드로 이동한다. 작성자는 편집기를 사용하고 다른 리드·관리자는 질문지 형태에서 검토 요청만 추가한다. 설명 추가·수정·삭제는 DB에서도 질문지 작성자만 허용한다. 제작자명 조회는 게시된 미보관 질문지에 한정하며 profiles 접근 권한은 넓히지 않는다.
