# 학습법 관리와 질문 참조

학습법 관리는 `/dashboard?view=study`, API는 `/api/study`, 확정 저장은 `public.study`다. 컨설턴트는 본인 확정본, 리드·관리자는 전체 확정본을 읽으며 수정·삭제는 작성자만 가능하다.

## 현재 입력 계약

- 제목 / 이름은 선택, 최대 100자다. 비어 있으면 학습 전략·기본 정보로 표시 이름을 만든다.
- 문제 상황 카드: 출처 → 학습법 적용 대상·교과·세부 과목명 → 단답형 문제 상황 → 선택 경험 내용 순이다. 세부 과목명은 미적분·확률과 통계처럼 해당 교과 안의 과목명이다.
- 출처는 `self`(자신 또는 지도한 학생의 경험), `template` 두 가지다. 과거 `student`는 `self`로 읽고 저장한다.
- 템플릿은 질의응답에서 선정한 19개 문장이다. 고3 국어 등급 하락·국어 내신 자료 부족 두 항목과 과목 공통 4개, 예비 고1 국어 모의고사·문법 우선순위 항목은 제외했다. 목록은 `lib/problem-templates.ts`에 있으며 DB 테이블이 아니다. 선택하면 문제 상황·학습법 적용 대상·교과·세부 과목명을 함께 채운다. 시험이 특정되지 않거나 여러 시험에 공통인 상황은 기타, 특정되지 않은 세부 과목명은 비운다. 기존 솔루션과 경험은 유지한다. 기존에 저장한 템플릿 본문을 새 문장으로 자동 교체하지 않는다.
- 선택창에는 고른 템플릿 문구를 표시하며, 본문이나 분류를 직접 수정해도 선택 표시를 유지한다. 다른 템플릿을 선택할 때만 바뀐다. 표시 상태는 블록별로 분리하고 저장 필드는 추가하지 않는다. 임시저장·확정본을 다시 열 때 본문과 일치하는 템플릿을 표시하며, 직접 수정한 본문은 ‘등록한 문제 상황’으로 표시한다.
- 문제 상황은 유형화된 짧은 문장이다. 구체적인 경험은 `values.problemExperience`에 선택 저장한다. UI 시안 단계의 미저장 경험은 DB에 존재하지 않아 소급 복원할 수 없다.
- 대응 솔루션 카드에는 학습 전략, 실천 가이드, 실천 기간 설정을 배치한다. 실천 가이드는 학생이 따라 할 수 있도록 순서·빈도 등을 명확히 작성한다.
- `values.periodEnabled`는 기본 `true`. 해제하면 기간이 없어도 확정할 수 있고 기존 기간 텍스트는 다시 체크할 때 사용하도록 보존한다. 해제 상태의 기간은 상세에서 ‘기간 설정 없음’으로 표시한다.
- 체크리스트는 항목을 추가·수정·삭제한다. 저장 계약은 기존 `values.checklist` 문자열을 유지하며 줄바꿈 하나가 항목 경계다. 기존 긴 서술은 임의로 요약하거나 쪼개지 않는다. 공백만 있는 체크리스트는 확정 불가다.
- 성적 결과 후속 진단·관련 자료 첨부·참고자료 입력 UI는 제거했다. 기존 `resultDiagnosis`, `references`, `reports` 및 Storage 파일은 삭제하지 않고 보존한다. 이번 변경은 파일 삭제나 Storage 정책 변경을 포함하지 않는다.

문제 상황·솔루션·실천 가이드·체크리스트·후속 전략과 분류 항목은 확정 시 필수다. 임시저장은 기존 localStorage/IndexedDB에 유지하며 구형 값은 읽을 때 경험 빈 문자열·기간 설정 true로 보완한다. 새 DB 함수는 구형 클라이언트가 새 필드를 생략할 경우 기존 값을 유지한다. revision 충돌·save ID 재시도·작성자 권한은 유지한다.

## 질문 참조

`@학습법`, 학습법 참조형, 학습법 참조 권장 안내를 유지한다. 탐구활동은 파랑·나침반, 학습법은 보라·책으로 구분하며 둘 다 권장일 때 함께 표시한다. 가이드 연결과 기존 접근 권한도 그대로 유지한다. 상세 화면에서 경험 내용과 항목별 체크리스트를 읽을 수 있다.

## 2026-10-12 검증 및 운영 상태

- 로컬 `20261012024650_study_solution_fields.sql` 적용 완료. 가상 기존 데이터의 원문·체크리스트·진단·첨부 메타데이터·삭제 상태 보존을 이전 리허설 후 롤백으로 검증했다.
- 신규 SQL 저장 회귀, 기존 `study_storage.sql`, `study_guide_reference.sql` 통과. 테스트 데이터는 롤백했다.
- 템플릿/UI/호환 6개와 기존 저장/API/질문 20개 JS 회귀, 타입·변경 파일 린트·Webpack 빌드 통과. 실제 브라우저 테스트는 수행하지 않았다.
- 운영은 읽기 전용 집계와 dry-run만 수행했다. 실제 migration·앱 배포는 하지 않았다. 당시 운영 최신 이력은 `20261012011802`, 학습법 1건(활성 1, student 출처 1, 첨부 0, 후속 진단 내용 0)이었다. 적용 직전에 다시 확인해야 한다.
- 로컬 security advisor 경고 없음, migration 이력 일치. DB lint에는 기존 질문/응답 함수 경고가 있으며 변경한 `save_study` 경고는 없었다.

운영 백업·적용·검증·복구는 [학습법 운영 적용 절차](study-methods-operations.md)를 따른다.

## 관리 목록 조회 (2026-10-13)

일반 목록은 공통 Table 기반으로 한 페이지에 최대10개를 표시한다. `/api/study?mode=table`은 `scope=own|others`, `page`, `q`(최대200자), `owner`(UUID)를 받고 `{ userId, activities, total, page, pageSize: 10 }`을 반환한다. 검색/작성자 필터/count/range는 DB에서 수행하며 기존 역할과 RLS를 유지한다. 수정일 내림차순·id 순서로 정렬하고 범위를 벗어난 페이지는 마지막 유효 페이지로 보정한다.

`mode=summary`는 `{ mine, others, people: [{ id, label, count }] }`을 반환한다. 전체 본문 대신 작성자 메타데이터만 집계한다. 브라우저 임시저장은 내 학습법의 저장 상태 선택창에서 별도로 검색·페이지 이동하며 서버로 전송하지 않는다. 확정본에 로컬 수정본이 있으면 열 때 그 수정본을 복원한다.

관리/등록 전용 화면은 전체 확정본 조회를 하지 않는다. 기존 파라미터 없는 API와 `useStudyList`는 참조·첨부 선택 호환을 위해 유지한다. DB migration은 추가하지 않았다. 타입·lint·관련 JS32개·Webpack 빌드, 로컬 인증 계정의 실제 조회 검증 통과. 브라우저 UI/운영 적용은 별도다.

### 임시저장 통합 목록 (2026-10-13)

앞 절의 확정/임시저장 분리 기본 화면을 대체한다. 내 학습법은 전체가 기본이며 임시저장을 최신순으로 먼저 표시하고 확정본을 이어 붙인다. 상태 필터는 전체/확정/임시저장이다. 확정본의 로컬 수정은 같은 ID 한 행으로 합치고 ‘수정 중 · 임시저장’으로 표시한다. 로컬 목록이 변경되면 내 학습법 전체·첫 페이지로 돌아오고 검색을 해제한다. 본문·첨부는 여전히 브라우저에만 보관한다.

조회 전용 POST mode=table에 로컬 대체 ID와 검색에 맞는 로컬 개수만 전달한다. 서버는 로컬 행의 자리를 빼고 필요한 확정본만 반환하여 합계 최대 10개를 유지한다. 로컬 대체 ID가 있을 때는 서버에서 검색 결과 ID만 500개씩 읽어 제외·집계한 후 해당 페이지 본문만 조회한다. 신규 임시저장만 있으면 기존 count/range 조회를 사용한다. 타인 scope에서는 로컬 ID/개수를 무시하고 기존 권한과 RLS를 유지한다. DB migration 없음, 운영 적용 없음.

검증: 타입 검사 및 관련 회귀 34개 통과. 실제 브라우저 테스트는 수행하지 않았다.

### 학습법 추가 새로고침 복원 (2026-10-13)

관리 목록의 새 학습법 추가는 studyEditor=new 쿼리를 유지한다. 현재 탭의 sessionStorage에 계정·Supabase 환경별로 작성 본문과 저장 기준본을 별도 보관해 새로고침 후 Drawer와 미저장 변경 여부를 복원한다. 명시적 임시저장 목록을 자동 생성하거나 덮어쓰지 않는다. 닫기/변경 내용 버리기/확정 시 복원 데이터와 해당 쿼리를 정리하고 다른 URL 파라미터는 보존한다. 이 복원은 현재 탭의 새 학습법 추가 범위이며, 타인 상세·질문 내 등록/참조 선택기에는 적용하지 않는다. 탭을 닫은 뒤에도 보관하려면 기존 임시저장을 사용한다. 브라우저 저장 실패는 오류 안내를 표시하고 현재 입력을 유지한다.

검증: 타입 검사·변경 파일 린트, 복원 데이터/기준본/계정 분리/삭제 회귀 3개 통과. 실제 브라우저 테스트와 운영 변경 없음.
