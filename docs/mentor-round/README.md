# 멘토라운드 페르소나와 판단 근거

## 목적과 한계

실제 제출 답변에서 이미 정리한 28명·71개 요약을 독립적인 전략·스킬·경험 구성요소로 구조화한다. 기존 `mentors.mjs`/`mentor-methods.mjs`의 임의 프로필과 태그는 새 투표와 멘토 소개에 사용하지 않는다. 학교 소속, 합격 사실 또는 AI 자기 확신을 신뢰도 점수로 사용하지 않는다.

이는 멘토 본인이 지금 내린 선택이나 내부 사고 과정을 재현하는 기능이 아니다. 원문을 바탕으로 AI가 현재 질문에 적용한 **간결한 판단 근거**를 제시한다. 원문을 읽을 수 없는 경우는 낮은 신뢰도와 구분한다. 실시간 원문 검증이나 멘토의 검수 없이 요약 자체가 정확하다고 보증하지 않는다.

## 저장 모델과 코드 책임

- `shared/persona-catalog.json`: 공개 가능한 기존 요약과 그 내용에 맞춰 붙인 짧은 태그. 이번 태그 정리는 AI가 수행했으며 멘토 본인의 검수로 간주하지 않는다. `id`, `version`, `kind`, `displayName`, `components`, `limitations`를 보관한다. 구성요소는 전략/스킬/경험, 진술, 출처 참조, 원래 페르소나·구성요소·버전의 계보를 가진다. 적용 조건과 예외는 아직 수집하지 않았음을 `applicability.status=not-collected`로 명시한다.
- 구성요소 ID는 멘토 ID와 발췌 해시를 조합한다. `evidence-<sha256>`는 원문 발췌의 안정적인 공개 참조다. 후보와 참조는 해당 멘토의 허용 목록에 속해야 한다. 같은 문장이 다른 멘토에게 있더라도 다른 멘토 구성요소를 선택할 수 없다.
- `server/persona-sources.json`: 기존 비공개 조회 매핑. 소유자·세션·질문·범위·해시는 서버에만 둔다. 공개 catalog에 소유자나 제출 세션 ID를 복사하지 않는다.
- `server/source-evidence.mjs`: 기존 소유자 조건과 SHA-256 검증을 그대로 사용한다. 해시 불일치/누락은 제외하고 살아남은 발췌의 ID는 바뀌지 않는다.
- `server/persona-ballot.mjs`: 검증된 원문을 가진 구성요소만 후보로 전달하고 모델 결과를 별도 검증한다. 다른 멘토 ID, 알 수 없는 출처, 중복 참조, 잘못된 선택지, 빠진 대안 등을 거부한다.
- `server/vote.mjs`: 원문·구성요소 → 질문 조건 → 적용 기준 → 대안 비교 → 결론·한계의 설명 계약을 생성한다. 관련 구성요소가 없으면 태그를 억지로 붙이지 않는다.
- `server/comment-support.mjs`: 요약뿐 아니라 검증된 짧은 원문을 함께 대조한다. AI의 의미 판단이며 확정 판정은 아니다.

요약/태그/분류의 의미를 바꿀 때 구성요소와 페르소나 버전을 올린다. 원문·발췌 범위가 바뀌면 새 출처 ID와 구성요소 ID를 만들고 기존 저장 투표는 수정하지 않는다. 기존 공개 요약의 구조화이며 새 원문을 추가한 것이 아니다.

## API와 UI

기존 인증된 `POST /api/mentor-round/vote`의 `panel`, `mentor`, `q`, `opts` 요청은 유지한다. `mea28-v1`은 패널 정체성이다. 페르소나와 설명의 버전은 응답에 따로 보관한다.

기존 `choice`, `reason`, `applied`, `sources`, `support`에 다음을 추가한다.

- `persona`: 생성 당시 전체 페르소나 스냅샷. 재평가나 catalog 변경으로 덮어쓰지 않는다.
- `applied`: 안정적인 구성요소 `id`, 한국어 종류·태그, 현재 상황에서의 적용 문장, `sourceRefs`.
- `explanation`: 버전, 질문 조건 요약, 적용 구성요소와 근거, 선택하지 않은 모든 대안과 차이/변경 조건, 결론, 한계, AI 설명 고지.
- `confidence`: 원문 확인 범위(`sourceCoverage`), 적용한 출처의 확인 범위(`appliedCoverage`), 대조 완료/미완료, 한계. 적용한 원문이 있다는 것은 해당 적용 문장이 원문과 의미상 일치함을 보증하지 않는다.
- `sources`와 `support.sources`: `{id,summary,question,quote}`. 전자는 생성에 적용한 자료, 후자는 별도 AI 대조에서 지지한다고 판단한 자료다. 동일하지 않을 수 있다.

학생 화면은 멘토 소개, 선택과 자연스러운 조언, 실제 답변 원문 순서로 읽는다. 버전·구성요소·원문 커버리지 등 내부 관리 정보는 학생에게 나열하지 않는다. 결과의 전략·방법 태그를 누르면 해당 태그의 출처 ID에 연결된 실제 질문과 답변 발췌가 열린다. 전체 원문 보기와 태그별 보기는 같은 Dialog를 사용한다. 코멘트마다 생성 주체를 강조하지 않으며, 결과의 짧은 공통 안내로 멘토의 과거 경험을 재구성한 조언과 이번 질문에 대한 직접 답변을 구분한다.

새 응답은 설명 v3를 사용한다. `reason`은 검증된 원문·경험을 참고해 지금의 질문에 맞는 행동, 선택 이유, 확인할 점을 2~4문장의 존댓말 조언으로 생성하고 표시한다. 기존 v2의 모든 자유서술 차단 정책은 새 응답에 적용하지 않는다. 원문을 그대로 인용하거나 본인 경험·성적 향상을 지어내지 않도록 지시하며, 명시적인 1인칭 사칭·제작 과정 문구는 `validateAdvice`가 거부한다. 이 검사는 말투/형식 검사이며 의미상 과장·적용 정확성을 보증하지 않는다. `applied.evidence`는 검증된 구성요소의 요약으로 서버가 채우고 코멘트 아래에 중복 노출하지 않는다. 태그의 ID·출처 허용 목록 검증은 그대로 유지한다. 자동 근거 등급·재평가는 v3에도 제공하지 않는다.

저장된 v2는 연결된 `sources.summary`를 계속 표시하며 ‘이 질문으로 새 조언 받기’로 명시적으로 새 라운드를 생성할 수 있다. 이전 투표를 덮어쓰거나 현재 catalog를 사후에 끼워 넣지 않는다. 이전 응답의 태그 적용 문장이 코멘트에 이미 있으면 반복하지 않는다. 이전 원문 대조 근거는 생성 당시 참고 자료와 별도 표시한다. 내부 스냅샷과 검증 메타데이터는 localStorage에 그대로 보존한다. 화면 진입·기록 복원 시 자동 재생성이나 polling은 없다.

질문함의 기존 사용자별 localStorage에 투표 스냅샷을 저장한다. 새 서버 영속 저장·공유·삭제 API는 없다. 중단된 요청 복원, 재시도, 기존 12인 패널과 이전 28인 투표는 유지한다. 예전 투표에 현재 페르소나/설명을 사후 생성해 끼워 넣지 않는다. 재평가는 기존 `support`만 갱신하며 생성 당시 커버리지와 스냅샷은 유지한다.

## 권한과 데이터 전송

기존 로그인·온보딩·학생/리드 표시 역할 검사, same-origin 검사, 서버 비밀키 사용, 응답 `no-store`를 유지한다. DB 권한이나 스키마 변경은 없다. 브라우저가 출처 소유자/세션/원문 범위를 지정할 수 없다.

런타임에는 검증된 짧은 원문과 요약을 OpenAI에 전달한다(`store:false`). 전체 제출본과 소유자·세션 등 비공개 조회 식별자는 전달하지 않는다. 원문 발췌 허용 목록을 바꿀 때 개인정보 검토와 원문·요약 검수를 함께 수행해야 한다. 초기 패치 검증은 오프라인이었다. 아래 2026-11-05 로컬 검증에서 실제 API 호출과 개발 DB 읽기 경로를 확인했다.

## 향후 합성 페르소나

`composePersona`는 명시적인 원본 페르소나 ID·구성요소 ID·버전을 받아 독립 사본과 계보를 보존하는 초안만 만든다. 중복/없는 구성요소와 버전을 거부한다. `synthetic` 및 `needs-review`를 강제하며 실제 멘토의 정체성·학력은 상속하지 않는다.

합성 UI/저장/API 투표는 아직 연결하지 않는다. 혼합된 적용 조건, 반대되는 조언, 원본 멘토 간 맥락 차이는 자동으로 해결했다고 주장하지 않는다. 향후 검토·충돌 해소·명시적인 활성화 절차가 필요하다.

- `npm run lint` 및 변경 파일 대상 ESLint

DB migration 없음. 앱 배포·운영 API/DB 연결 검증은 미수행이다. API 키 없이 실행한 모의 검증은 실제 모델의 한국어 설명 품질·개인정보 제거·상황 적합성 검증을 대체하지 않는다. 운영 사용 전 검수자가 원문과 요약/태그를 비교하고 조건 누락·반대 조언·입시 사실 환각을 점검해야 한다. 그 후 승인된 환경에서 실제 응답 품질을 확인한다.

### 로컬 적용·실제 호출 검증 (2026-11-05)

- 기준 HEAD `482a2628e8cfc583e124102fbdc1c089afee231d`, 깨끗한 작업 트리에서 다운로드 패치를 `git apply --check` 후 적용했다. 커밋·푸시·배포·DB 변경 없음.
- 실제 `gpt-4.1-mini-2025-04-14` 호출 20회(선택 생성 12회, 원문 대조 8회), 모두 HTTP 200. 입력 21,013 / 출력 3,891 토큰이 보고되었다. 유료 API 사용량이며 청구 금액은 확인하지 않았다.
- 첫 4회는 개발 모드 미설정으로 원문이 없는 경로였다. 이후 `NODE_ENV=development`로 로컬 DB의 빈 제출 결과에 대한 기존 해시 검증 fixture 경로를 사용했다. 운영 DB의 실제 제출 조회 성공 검증이 아니다.
- 개념 보완, 확신 없는 정답 복습, 입시 합격 보장, 실험 변수 비교를 점검했다. 원문 미확인은 태그 없음/평가 미완료로 표시되고, 원문 연결 후 전략·스킬 ID와 출처가 연결되었다.
- 강제 선택 때문에 근거 없는 입시 우열을 암시하는 문제가 있어 `choice=-1` 판단 보류를 추가했다. 보류 시 모든 대안의 비교를 필수로 검증하며 클라이언트도 정상 응답으로 처리한다. 합격 보장 사례는 재검증에서 보류하고 공식 모집요강 확인을 안내했다.
- 적용 문장에 원문에 없는 실행 절차를 과거 경험처럼 넣거나 확장 적용을 상으로 평가하는 사례가 발견돼 생성·대조 지침을 강화했다. 그러나 최종 실험 사례에서도 원문에 없는 단일 변수 조절 경험이 암시되고 대조가 상으로 나왔다. **의미상 과장과 AI 대조 과대평가가 완전히 해결된 것은 아니다.** 출처 ID 검증과 의미 정확성 검증을 구분해야 하며 운영 전 사람 검수 또는 별도 주장 단위 검증이 필요하다.
- 최종 오프라인 회귀 28개, 타입 검사(`--incremental false`), 변경 코드 ESLint, Webpack 프로덕션 빌드 통과. 기본 타입 검사 첫 실행은 tsbuildinfo 쓰기 제한으로 실패하여 증분 캐시 쓰기 없이 재실행했다.
- 브라우저 및 인증된 HTTP 라우트 전체 흐름은 미실행. 실제 테스트는 서버 vote 함수를 호출하여 기존 읽기 경로와 실제 OpenAI 통신을 검증했다. 28명 전체나 모든 질문 유형의 품질을 보장하지 않는다.


### 출력 경계 보완 (2026-11-05 후속)

프롬프트 강화만으로 과거 경험 과장과 대조 과대평가가 해결되지 않아 새 응답은 설명 버전 2를 사용한다. 모델은 후보를 선택하지만 자유 서술(reason/context/evidence/tradeoff/caveats)은 사용자 응답에 복사하지 않는다. 서버가 원래 질문·선택지·검증된 구성요소 ID로 제안과 출처 연결을 구성한다. 원문 발췌는 별도로 제공하며 새 제안이 과거 경험이나 입증된 효과가 아님을 명시한다. 모델 기반 근거 등급 호출을 생략하고 support=null 및 적합성 미검증으로 표시한다. v2 UI는 과거용 재평가 버튼을 제공하지 않는다. 이전 저장 응답은 변경하지 않는다.

이것은 의미 검증을 완성한 것이 아니라, 검증하지 못한 서술을 차단한 보수적 출력 정책이다. 구체적인 이유·대안별 장단점은 현재 축소되어 있고, 모델의 구성요소 선택 자체가 상황에 적합한지 및 기존 요약/태그가 정확한지는 여전히 사람 검수가 필요하다. 기존 v1 저장 응답과 재평가 기능에는 앞서 보고한 위험이 남는다.

실제 API 4회 추가 검증 모두 HTTP 200: 강의 보완·정답 복습·변수 비교는 새 제안으로, 합격 보장은 판단 보류로 표시됐다. 모든 결과에서 자동 등급이 없고 과거 경험을 생성한 문장은 노출되지 않았다. 추가 입력 7,048·출력 1,506토큰 사용(누적 24회, 입력 28,061·출력 5,397토큰). 과금 대상이며 실제 청구 금액 미확인. 오프라인에 악의적인 경험 문장과 상 등급을 강제로 넣어도 공개 응답에 나오지 않는 회귀를 추가했다.

### 읽기 중심 UI (2026-11-06)
결과는 넓은 답변 행과 적용 태그로 표시하고 원문 Q&A는 MentorEvidenceDialog에서 연다. 기존 판단 근거·페르소나 스냅샷·커버리지도 팝업에서 확인한다. PersonaEvidenceDetails는 이전 구조화 설명을 보존한다. 구조화 personas 소개와 설명 v2의 자동 등급·재평가 차단을 유지했으며 UI 전용 구형 패치의 임의 프로필 복귀 부분은 적용하지 않았다. 회귀 36개·타입·린트 통과, 가상 자료로 팝업/필터 브라우저 확인 후 임시 페이지 제거.

### 학생 사용 흐름과 문구 정리 (2026-11-06)

- 멘토 패널→멘토 소개, 개표 결과→투표 결과로 변경했다. 질문 입력은 고민 예시·입력 도움말을 제공하고 MEA 전략 적용 상태는 별도 안내 영역에 표시한다. 공통 Dialog의 닫기 버튼을 한국어로 맞췄다.
- 전략 이름도 ‘과업 집중기 분량 조절’→‘할 일이 몰릴 때 공부량 조절하기’처럼 풀어 썼다. `presentation.ts`에서 표시 이름만 공통 변환하며 catalog·저장된 이름·ID·출처·버전은 변경하지 않는다.
- 반복되던 적합성 미검증·구성요소·버전·커버리지 설명을 학생 UI에서 제거하고 실제로 참고한 경험 요약과 태그별 원문을 우선한다. 이는 표현·정보 배치 변경이며 적용 적합성을 새로 검증한 것은 아니다. API 생성 정책, 원문 검증, 권한, 저장 모델은 바꾸지 않았다.
- 원문 팝업은 질문→멘토 답변 발췌→선택적 요약 순서다. 원문이 없는 이전 기록은 짧은 빈 상태와 기존 원문 확인 동작을 제공한다. v2에는 등급을 새로 만들거나 예전 재평가를 연결하지 않는다.
- 로컬 테스트 학생의 기존 기록과 실제 새 질문을 사용했다. 질문 초안 1건·멘토 응답 28건을 생성했고 28/28 응답 완료를 확인했다. 실제 서비스 화면에서 데스크톱 1280px·모바일 390px 배치, 선택지 필터, 태그별/전체 원문 구분, Escape 닫기 후 원래 태그로 포커스 복귀, 가로 넘침 없음, 이전 저장 응답의 중복 제거를 확인했다. 타입 검사·변경 ESLint·관련 회귀 38개·diff 공백 검사 통과. 모델의 주제 연결 품질을 새로 검증한 것은 아니다. DB 변경·마이그레이션·운영 배포·커밋·푸시 없음.

### 경험을 엮은 조언형 코멘트 (2026-11-06)

사용자 요청에 따라 코멘트의 ‘AI가 제안’ 머리말과 경험 나열을 자연스러운 조언으로 변경했다. 설명 v3에서만 생성된 `reason`을 표시하고, 전략 태그와 원문 Dialog는 유지한다. 결과 공통 안내는 과거 경험을 재구성한 조언이라는 점만 간결하게 설명한다. 이전 요약형 기록은 그대로 남기고 같은 질문의 새 조언을 별도 라운드로 받을 수 있다. DB·원문 접근·API 키·모델 변경 없음. 로컬 반영이며 운영 배포는 하지 않았다.

타입 검사·변경 코드 ESLint·관련 회귀 41개·diff 공백 검사 통과. 실제 로컬 학생 화면에서 같은 질문의 새 라운드와 자연스러운 조언, 태그별 원문 Q&A 연결을 확인했다. 첫 검증 라운드는 개발 서버 연결 중단으로 완료되지 않았고, 연결 복구 후 별도 라운드는 27명 성공·1명 실패에서 명시적 재요청으로 28/28 완료했다. 자동 반복 요청은 추가하지 않았다. 원문 조회는 기존 로컬 개발용 검증 fixture 경로를 포함하므로 운영 DB 조회 성공이나 모든 질문에서의 조언 품질을 검증한 것은 아니다.
