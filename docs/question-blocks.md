# 질문 블록 관리

2026-09-23 운영 반영 완료: 아래의 로컬 전용·운영 미적용 문구는 각 구현 시점의 기록이다. 현재 `20260923085519`까지 운영에 적용했으며, [운영 반영 기록](production-db-rollout-20260923.md)에 검증 결과를 정리했다.

질문 편집은 `?view=questions&question=<질문 UUID>`로 연다. 목록에서 질문을 누르거나 새 질문을 만들면 브라우저 방문 기록을 추가하며, 뒤로가기·앞으로가기는 URL에 맞춰 목록과 편집기를 전환한다. 새로고침·직접 접속도 같은 질문을 연다. `question=new`는 새 UUID 주소로 교체한다. 임시 내용은 사용자·질문 ID별로 보존하여 질문 사이를 이동해도 서로 덮어쓰지 않으며, 이동 전 질문의 저장 응답은 해당 질문의 저장 상태만 갱신한다.

질문 블록은 질문 하나와 그 질문의 답변 열, 행 구성, 다른 질문과의 관계를 함께 저장한다. 리드·관리자는 대시보드의 데이터 관리 → 질문 관리에서 블록을 만들고 목록을 검색할 수 있다. 리드는 본인이 만든 블록을 수정·보관하고, 관리자는 모든 블록을 수정·보관할 수 있다. 두 역할 모두 활성 블록을 읽고 자신의 새 블록에서 참조할 수 있다.

이 기능은 질문지와 독립된 첫 단계다. 기존 질문지의 제작·배포·응답 저장 흐름에는 연결하지 않았다. 질문 블록의 선후관계와 조건은 **정의·저장·검증**되며, 컨설턴트에게 질문을 보여주거나 실제 답변에 따라 조건을 평가하는 기능은 아직 없다. [향후 답변 자료와 조건의 설계안](consultant-qa-data-design.md)은 별도로 유지한다.

한 블록에는 관리용 이름, 질문 문구, 1~20개의 답변 열이 있다. 질문 문구는 질문 관리 전용 서식 편집기를 사용한다. 질문지의 편집 요소와 관련 타입·서식 처리를 questions 폴더에 복제했으며 질문지 폴더를 참조하지 않는다. 열은 서술형·척도형·단일선택형·다수선택형 중 하나이며, 질문 관리 전용 카드로 유형을 설정한다. 질문 입력은 별도 카드로 분리하고 그 아래에 답변 열 카드를 배치한다. 각 카드에서 답변 유형과 열 제목을 편집하며, 미리보기에도 열 제목을 표시한다. 척도 점수·라벨, 선택형의 목록/칩 표시·직접 입력 항목을 설정할 수 있다. 선택형·척도형 안의 추가 서술 입력은 제공하지 않고 별도의 서술형 열을 추가한다. 기존 추가 서술 설정은 저장 형식 호환을 위해 유지하지만 질문 관리 편집·미리보기에서는 사용하지 않는다. 행은 한 행, 최대 20행까지 추가, 앞선 블록의 서술형 열을 기준으로 행 참조 중 하나로 설정한다. 화면에서는 선행 블록을 하나 지정하고, 여러 조건을 모두 만족하거나 하나 이상 만족하도록 설정할 수 있다. 조건은 다른 블록의 답변 유무, 텍스트·선택값의 일치, 다수선택 포함, 척도 점수 비교를 지원하는 정의다.

`public.questions`는 질문지 테이블과 외래 키로 연결되지 않는다. 열과 조건은 제한된 JSONB로 보관하며 블록 ID, 작성자, 참조 원본 블록 ID, 선행 블록 ID, revision, 보관 시각은 독립 열로 보관한다. 모든 신규 쓰기는 `save_question` 또는 `archive_question` RPC를 통해 진행된다. 직접 테이블 쓰기는 허용하지 않는다. 작성자·관리자 권한, 기대 revision, 중복 재시도, 참조 대상의 존재, 조건에 쓰는 열과 선택지의 타입, 순환 관계를 DB에서 확인한다. 다른 활성 블록에서 참조 중인 블록은 보관할 수 없고, 참조된 블록의 열 정의·행 구성도 바꿀 수 없다.

로컬 migration은 `20260923062030_create_question_blocks.sql`과 `20260923065223_question_block_editor_settings.sql`이다. 운영에는 적용하지 않았다. 같은 이름의 질문 블록을 여러 개 만드는 것은 허용하고 내부 UUID로 구분한다. 보관은 원본 내용을 지우지 않고 목록에서 제외한다.

편집 중인 질문 블록은 10초마다 서버 저장을 시도한다. 현재 저장 API는 질문·답변 열과 선택지 설정이 완성된 블록만 받으므로, 필수 내용이 비어 있는 동안에는 이 브라우저의 로컬 저장소에 임시 보관하고 입력 완료 후 서버에 자동 저장한다. 같은 브라우저에서 다시 열면 임시 내용을 복원한다. 저장 중 추가로 입력한 내용은 화면에 유지하며 다음 주기에 저장한다. 저장 결과가 불분명하면 같은 요청 ID로 재시도하고, revision 충돌이 나면 작성 내용을 보존한 채 저장을 멈춘다.

검증은 `supabase/tests/questions.sql`을 로컬 DB에서 롤백 트랜잭션으로 실행한다. 저장과 동일 요청 재시도, 오래된 revision, 역할별 읽기·쓰기, 직접 쓰기 금지, 잘못된 참조와 순환, 참조 중 수정·보관 차단을 확인한다. 실제 브라우저 테스트는 별도 요청이 없으므로 수행하지 않는다.

로컬과 운영의 마이그레이션 이력 차이는 [로컬 Supabase 안내](local-supabase.md)를 따른다. 동등성 검토 없이 운영 `db push`, reset, migration repair를 실행하지 않는다.

편집/미리보기 탭에서 사용자 답변 화면을 확인할 수 있다. 미리보기의 서술·척도·선택 답변과 반복 행은 화면 안에서만 체험하며 저장하지 않는다. 참조 행은 안내 예시로 표시하고, 질문 간 조건 실행은 아직 연결하지 않았다. 저장 버튼은 화면 상단에 두며 제작 화면 전체에만 회색 배경을 적용한다. 목록은 기본 배경을 사용한다. 제작 중 질문 표시는 #, 미리보기는 숫자로 표시한다.

`20260923070752_rename_question_blocks_to_questions.sql`은 테이블을 `public.questions`로 변경하고 저장/보관 RPC, 인덱스와 제약 이름도 맞춘다. API 경로는 `/api/questions`다. 기존 행과 권한을 그대로 유지하며 앞선 migration 파일은 이력으로 보존한다. 로컬 DB에만 적용했다.

관리용 이름은 카드 밖의 선택 입력이다. 비워두면 title을 빈 문자열로 보존하고 질문의 일반 텍스트를 목록·참조 선택 화면의 이름으로 사용한다. 질문을 수정하면 표시 이름도 함께 바뀐다. `20260923071712_optional_question_management_title.sql`을 로컬 DB에 적용했다.

## 질문 설명

`20260923073954_question_details.sql`은 `questions.id`를 참조하는 별도 `question_details` 테이블을 추가한다. 설명 항목의 UUID, 질문 ID, 표시 순서, 제목, 서식 본문, 컨설턴트 공개 여부, 생성·수정 시각을 저장한다. 질문 본문이나 답변 열에는 설명을 섞지 않으며, 향후 질문–답변 데이터 추출에서도 기본 제외하는 보조 자료다. 질문당 최대 20개, 제목 200자, 서식 본문 10,000자까지 저장한다. 부모 질문을 물리 삭제하면 함께 삭제하고 보관 시에는 유지한다.

질문 카드 아래에서 기존 질문지와 같은 설명 편집 UI를 제공한다. 관련 컴포넌트는 질문 관리 폴더에 복제했으며 질문지 컴포넌트에 의존하지 않는다. 미리보기에는 공개 설명만 표시한다. 답변 카드 아래의 `답변 열 추가` 버튼으로 열을 늘린다.

질문 API는 `details` 배열을 함께 조회·저장한다. `save_question`이 부모의 권한·revision·saveId를 확인하고 질문과 설명을 한 트랜잭션에 저장하므로 기존 10초 자동저장·수동저장·로컬 임시저장·충돌 보호가 설명에도 적용된다. 배열을 생략한 구버전 요청은 기존 설명을 보존하며 빈 배열은 전부 삭제한다. 다른 질문의 설명 ID를 재사용할 수 없다. 설명 테이블은 리드·관리자 읽기만 허용하고 직접 쓰기를 차단한다. 컨설턴트 공개 여부는 향후 배포 화면용 표시 설정이며 현재 독립 질문 라이브러리에 컨설턴트 접근 권한을 부여하지 않는다.

로컬 DB에만 적용했다. `supabase/tests/question_details.sql`에서 분리 저장·재조회·동일 요청 재시도·설명 수정/삭제·생략 시 보존·충돌·타 질문 ID 탈취 및 부분 저장 차단·권한·연쇄 삭제를 검증한다.

답변 열 아래의 `최대 [숫자]개 항목 입력 (반복 블록형)`에서 1~~20을 직접 입력한다. 기본값 1은 단일 입력, 2~~20은 반복 입력으로 저장한다. 기존 rowMode/maxRows 저장 계약과 자동저장을 사용한다. 참조 입력은 별도의 `앞선 답변의 항목 가져오기`로 설정하고 반복 입력과 동시에 선택할 수 없다. 반복 입력 미리보기는 답변 열 제목과 행별 답변 요약을 표로 표시한다. 행을 누르면 바로 아래에 기존 열별 입력 UI가 펼쳐지며 한 번에 하나의 행만 열린다. 다른 행으로 이동하거나 접어도 입력값은 행 ID별로 유지된다. 표의 마지막 전체 너비 행에 있는 `항목 추가`를 누르면 새 항목이 바로 펼쳐지고, 삭제 시 다른 행의 값은 유지한다. 현재 항목 수와 최대 수를 표시한다. 미리보기 답변은 저장하지 않는다.

다수선택형 미리보기는 하나의 직접 입력 선택지에서도 응답자가 `직접 입력 답변 추가`로 여러 답변을 작성·삭제할 수 있다. 각 입력은 선택지 id와 별도 entryId를 가진 `{id,text,entryId}`로 구분하고 표 요약에도 모두 표시한다. 기존 `{id,text}` 입력도 읽는다. 단일선택형은 직접 입력 하나만 허용한다. 이 형식은 현재 질문 관리 미리보기 상태에만 적용하며 기존 질문지 응답 저장 API/DB는 바꾸지 않는다. 회귀 검증은 `scripts/verify-question-preview-direct-input.mjs`이다.

조건 편집 UI는 단계적 재설계를 위해 `[질문 선택] 질문에 [조건 선택] 때` 형태로 교체했다. 자신을 제외한 저장된 질문을 고를 수 있다. 현재 선택은 화면 상태에만 유지하고 조건 선택란은 비활성이다. 기존 condition 데이터는 다른 항목 저장 시 보존하며 이 UI에서 새 조건을 저장하거나 실행하지 않는다.

## 응답 조건과 항목 참조

행 구성·선후관계 별도 카드를 제거했다. 조건 카드의 `[질문] 질문에 [응답했을 때]` 선택을 저장하며, 조건 아래 `앞선 질문의 응답 참조`를 켜면 sourceBlockId를 해당 질문으로 설정하고 rowMode를 reference로 저장한다. 최대 항목 수는 직접 설정하지 않고 앞선 응답 항목 수를 따른다. 참조 해제 시 단일 입력으로 돌아가며 필요한 최대 항목 수를 다시 설정할 수 있다. 조건이나 대상 질문을 바꿀 때 기존 참조를 함께 정리한다.

질문 전체의 answered 조건은 fieldId를 생략한다. 질문 전체 참조는 sourceFieldId를 null로 저장하고 동일 질문의 질문 단위 answered 조건을 요구한다. 기존 열 단위 조건·서술형 열 참조는 호환 유지한다. `20260923083334_question_response_references.sql`은 데이터 행을 변경하지 않고 이 검증 계약만 확장하며 로컬 DB에만 적용했다.

미리보기에는 앞선 질문의 응답 입력도 제공한다. 어느 한 열에 실제 답변이 있는 행을 작성한 항목으로 세고, 빈 행은 제외한다. 각 원본 행 ID에 대응하는 후속 행을 하나씩 보여주며 참조 행은 직접 추가·삭제하지 않는다. 원본 행을 삭제하거나 내용을 비워도 다른 행과 연결된 후속 답변을 덮어쓰지 않는다. 숨겨진 후속 답변은 미리보기 상태에 보존하고 다시 조건이 충족되면 복원한다. 실제 컨설턴트 응답 저장·배포 연결은 별도 단계다. 검증: `supabase/tests/question_response_references.sql`, `scripts/verify-question-reference-rows.mjs`.

## 특정 선택지 조건

조건 카드에 `특정 항목을 선택했을 때`를 추가했다. 직접 입력(isOther)이 하나도 없는 단일·다수선택형 열만 대상이며 후보 열이 하나면 자동 선택한다. 여러 열이면 답변 열을 먼저 지정하고 선택지 하나를 고른다. 단일선택은 equals, 다수선택은 includes로 기존 조건 계약에 저장한다. 대상 질문이나 열을 바꾸면 이전 선택지 조건값을 지워 잘못된 조합을 저장하지 않는다. 조건이 완성되기 전에는 로컬 초안만 유지하고 서버 자동저장은 대기한다.

참조를 끄면 조건에 맞는 앞선 행이 하나라도 있을 때 현재 질문을 입력할 수 있다. 참조를 켜면 조건을 만족하는 원본 행만 일대일로 가져오고, 원본 행 ID로 입력 내용을 보존한다. 미응답·삭제된 선택지·잘못된 선택값은 조건을 충족하지 않는다. 이 동작은 현재 미리보기에서 제공하며 실제 컨설턴트 배포/응답 저장은 아직 연결하지 않았다.

`20260923084501_question_choice_reference_conditions.sql`은 고정 선택형 조건으로 필터링한 질문 전체 참조를 허용한다. DB의 선택지 존재·열 유형·순환·권한 검증은 유지하며 기존 데이터 행은 변경하지 않았다. 로컬에만 적용했다. 검증은 `scripts/verify-question-choice-conditions.mjs`와 `supabase/tests/question_choice_conditions.sql`이다.

## 열을 먼저 고르는 조건 UI

조건 카드의 선택창은 공통 Select 컴포넌트를 사용하며 `[질문] 질문의 [열 제목 열에서 / 모든 열에] [조건]` 순서로 구성한다. 모든 답변 열을 고를 수 있고, 직접 입력 없는 선택형 열에만 `선택했을 때`를 표시한다. 이 조건을 선택하면 같은 줄에 `[선택지] 항목을` 입력이 나타난다. 사용할 수 없는 조건은 비활성 항목으로 남기지 않고 메뉴에서 제외한다. 질문·열을 바꾸면 이전 선택값은 지우고 응답 조건으로 되돌린다.

특정 열의 `응답했을 때`는 그 열만, `모든 열에 응답했을 때`는 같은 원본 행의 모든 열을 확인한다. 서로 다른 행의 일부 답변을 합쳐 전체 응답으로 취급하지 않는다. 참조를 켜면 이 조건에 일치하는 행만 반복한다. `20260923085519_question_answered_column_references.sql`은 기존 열 존재 검증을 유지하면서 특정 열의 answered 조건으로 질문 전체 행을 참조할 수 있게 허용한다. 로컬 적용·사전 롤백 테스트·기존 질문 저장 회귀·DB lint/advisor·빌드 검증을 완료했다.

## 질문 목록: 테이블·그래프

질문 관리 목록은 테이블을 기본으로 하고 상단에서 그래프로 전환한다. `QuestionManagementTable`은 질문·조건·관리 열을 표시하며 질문 열에 너비의 45%를 배정한다. 조건의 질문 이름, 열 제목, 선택값을 배지로 구분한다. 긴 배지는 말줄임하고 마우스를 올리면 전체 값을 확인할 수 있다. 수정 권한이 있는 행을 누르면 기존 질문 URL로 이동하며 보관 버튼은 편집 이동과 분리한다.

`QuestionRelationshipGraph`는 조건·응답 참조·선후관계를 앞선 질문 → 후속 질문 화살표로 표시한다. 화살표 위에 열·선택값·조건을 작은 글씨로 표시한다. 열 제목과 ‘모든 열’은 배지로 표시하며 같은 두 질문의 여러 조건은 한 연결로 묶고 AND/OR와 참조 설명을 구분한다. 확대·축소와 가로·세로 스크롤을 지원하며 질문을 누르면 편집으로 이동한다. 검색 결과에는 조건의 출처를 잃지 않도록 앞선 질문들을 함께 배치한다. 연결 없는 질문도 표시한다. 목록 검색·보기 방식은 편집 후 브라우저 뒤로가기 시 유지된다.

표시 문구와 위상 정렬 기반 배치는 `lib/question-list.ts`에서 관리한다. `scripts/verify-question-list-graph.mjs`는 분기·합류·노드 겹침·검색 시 선행 질문 보존·조건과 참조 문구 구분·순환/누락 관계 방어를 검증한다. 기존 질문 데이터와 API 계약은 변경하지 않는다.
