# MEA UI UX 개선 진행 기록

최종 갱신: 2026-10-16

이 문서는 현재 대화에서 합의한 개선 방향과 완료 상태를 보관하는 인계 기준이다. 대화 요약 후에는 이 문서와 실제 변경 파일을 확인하고 이어서 작업한다.

### 서비스 공지 (2026-10-16)

- 관리자 메뉴에 서비스 공지 편집·미리보기·표시 기간·즉시 종료를 추가했다. 공통 UI를 사용하며 DB revision으로 동시 수정을 보호한다.
- 로그인한 사용자에게 고정 상단 배너를 표시한다. Realtime과 30초 보완 조회/탭 복귀로 배너만 갱신하며 페이지 새로고침·입력 초기화를 하지 않는다. 닫은 뒤 내용이 바뀌면 다시 표시한다.
- 공지 전용 DB만 추가하고 기존 질문·답변·임시저장은 변경하지 않는다. 기준 문서는 `docs/announcements/`다. 실제 브라우저 테스트·운영 배포는 수행하지 않았다. 최초 도입 전에 이미 열린 구버전은 공지를 수신하지 못한다.

### 컨설턴트 질문지·회원 관리·내 정보 공통 UI (2026-10-15)

- 컨설턴트 질문지 목록을 공통 CollectionTable/Table·CollectionTableState 기반 표로 통일했다. 제목/배포일·답변 상태·열기를 정렬하고 모바일에서는 상태를 제목 아래에 표시한다. NEW, 제출 전/완료 탭, 서버 10개 페이지와 상세 이동·읽음 동작을 유지한다. 로딩/빈 상태도 표 머리글과 본문 높이를 유지한다.
- 학생·컨설턴트 관리는 CollectionHeader, 공통 표·빈 상태를 사용한다. 중복 목록 제목과 아바타를 제거하고 인원수를 표 위에 배치한다. 학생은 모바일 이름 아래 가입일, 컨설턴트는 이름/가입일 아래 직책을 표시하여 긴 이름과 역할 선택이 겹치지 않게 한다. 두 도메인의 목록 컴포넌트는 독립적으로 유지한다.
- 내 정보는 공통 헤더·accent Card·Label·Input·Button을 사용한다. 읽기 정보는 회색 필드, 이름 저장은 입력 옆 기본 버튼으로 정리하고 상태 문구 자리를 확보한다. 학생 이름 읽기 전용, 회원 유형/학기와 기존 저장 권한은 유지한다.
- 공통 CollectionPagination에 표와의 위쪽 간격을 적용했다. 다른 목록에도 동일하게 적용된다. 데이터/API/권한·DB 변경 없음. 타입 검사·변경 파일 린트·기존 목록 URL/대시보드 접근/직책 변경 테스트 12개 통과. 실제 브라우저 테스트와 운영 반영은 미수행이다.

### 제출 오류 안내 디자인 보완 (2026-10-15)

- 카드 밖의 오류 문구와 전체 빨간 외곽선을 제거하고, 질문 제목 아래 카드 안에 안내를 배치했다. 노란 카드 테두리는 유지하며 옅은 오류 배경, 작은 아이콘·제목, 중립색 상세 문구로 구분한다.
- 검증 기준·자동 스크롤·오류 목록 이동·저장 동작은 유지한다. 실제 브라우저 테스트는 수행하지 않는다.

### 제출 오류 안내·질문 이동 (2026-10-15)

- 질문지 전체 제출 전에 질문별 필수 답변/항목 수/유형/진로 필수 시기를 검사한다. 첫 오류 질문으로 자동 스크롤·포커스하고, 상단 목록에서 개별 질문으로 이동한다. 질문별 안내에 항목과 열 이름을 표시한다.
- 답변을 수정하면 해결된 오류가 바로 사라진다. 편집·임시 저장은 유지하며 숨겨진 질문의 보존 답변을 제출 조건 판정에 사용하지 않는다. 질문·팝업을 강제로 펼치지 않고 문제 질문에 표시한다.
- 기존 서버 검증·제출 단위·DB·권한·저장 데이터 변경 없음. 타입 검사·린트·제출/조건/참조 관련 JS 33개 검증. 실제 브라우저 테스트는 요청이 없어 미수행이다.

### 답변 데이터·API·코드 정리 (2026-10-15)

- 가이드 정의 변경과 원격 답변 변경이 함께 발생할 때 오래된 답변을 재저장하던 오류를 수정했다. 미수정 화면은 최신 답변을 반영하고, 동시 편집은 로컬 입력을 보존한 채 저장을 잠근다.
- 진로 흐름의 필수 두 시기 그룹을 질문 데이터로 옮겨 화면·DB 제출 검사를 맞추고, 질문 불러오기에서도 새 열 ID에 연결한다. 전용 입력/읽기 팝업과 기존 디자인은 유지한다.
- 응답 화면·편집 세션·HTTP·요청 schema·제출 조회를 분리했다. 제출 목록은 서버 10개 페이지, 한 사람의 상세는 선택 시 조회한다. PDF는 경량 제출 목록 이후 한 사람씩 처리하며 버튼 진행 표시와 PDF 모양을 유지한다.
- 배포 권한, 작업 답변 비공개, 최종 제출 snapshot, 가이드 지정 계정, 기존 답변과 시각을 보존한다. 질문별 제출 오류 목록 UX는 이번에 변경하지 않는다.
- 로컬 migration 롤백 시험·적용, 기존 SQL 6개 및 신규 가상 데이터 롤백 회귀, 관련 JS·타입·린트·Webpack 빌드 통과. DB 보안/함수 검사 오류 없음. 운영 반영·실제 브라우저 검증은 미수행이다. 계약과 적용 절차는 질문 기준 문서 참조.

### 검토 요청 배경 정리 (2026-10-15)

- 공통 `QuestionReviews`의 바깥 카드는 기본 배경에 질문 카드와 같은 2px 초록색 상단 테두리를 적용했다. 옅은 초록색 배경은 실제 미처리 요청 내용이 담긴 내부 박스에만 적용하며 완료 이력은 기존 기본 배경을 유지한다. 어두운 테마도 대응한다.
- 질문 편집기와 질문지에 함께 적용되며 펼침·읽음 처리·요청 작성/완료 동작과 API·DB 계약은 유지한다.
- 검증: 타입 검사·변경 파일 린트·diff 공백 검사 통과. 실제 브라우저 테스트·프로덕션 반영은 하지 않았다.

### 질문 단위 데이터/API/코드 정리 (2026-10-15)

- 검토 요청 개수를 DB 집계로 바꿔 1,000행 제한에 의한 누락을 방지하고 미확인 개수도 한 번에 조회한다. 목록의 역참조 조회는 현재 페이지 ID에 한정하고 조건 인덱스를 추가했다.
- 질문 저장 오류에 항목 경로와 구체적 설명을 제공하고 설명 ID 중복을 API/편집기에서도 검사한다. 기존 충돌·삭제 확인·재시도 계약은 유지한다.
- 목록, 편집 UI, 편집 세션, 로컬 초안, 서버/요청 schema/오류 변환을 분리했다. 기존 디자인·자동 저장·URL·확인창·질문지 내 편집 동작은 유지한다. 제출 검증 개선은 후속 작업으로 남긴다.
- 로컬 migration 적용·권한/집계 SQL 롤백 회귀·관련 JS 68개·타입/린트·Webpack 빌드 통과. 로컬 보안 검사 경고·오류 없음. 운영/실제 브라우저 검증은 미수행. 세부 계약과 운영 절차는 질문 문서를 따른다.

### 질문 편집 로딩 UI (2026-10-15)

- 질문 상세 로딩 문구를 공통 Skeleton/Card 기반 편집기 스켈레톤으로 교체했다. 독립 Drawer와 질문지 내 편집기에 함께 적용하고 참조 질문 로딩도 처리한다.
- 수정 화면 제목과 하단 버튼 영역을 유지하며 이전 질문의 저장 안내가 노출되지 않도록 했다. 오류 재시도와 기존 입력·저장 동작은 유지한다.
- 검증: 타입 검사·변경 파일 린트·질문 편집/답변 유형 회귀 28개 통과. 실제 브라우저 테스트·운영 반영은 미수행.

### 질문 제작 공통 컴포넌트 통일 (2026-10-15)

- 답변 표시 방식·행 수 설정의 직접 스타일 카드를 공통 accent Card/CardContent로, 조건 내부 박스를 공통 Card/CardContent로 교체했다. 현재 디자인과 중첩 배치·여백은 유지한다.
- 참조 권장·선택형/척도형·설명 제목/공개 라벨을 공통 Label로 통일했다. 서식 입력과 미리보기 공유 표면은 유지한다.
- 가이드 응답이 있는 열 변경 및 저장 중 추가 확인 두 경로를 공통 AlertDialog로 전환했다. 배경 잠금·취소 초기 포커스·닫힘 문구 유지·중복 확인 방지와 취소/승인 저장 동작을 검증한다. API/DB 변경 없음.
- 검증: 타입 검사·변경 파일 린트·질문 편집/답변 유형 회귀 28개 통과. 확인 중 뒤로가기, 열 삭제/유형 변경 취소, 저장 중 취소의 자동 저장 중지, 승인 시 동일 saveId 재시도를 확인했다. 실제 브라우저 테스트·운영 반영은 미수행.

### 질문지 검토·배포 명칭 통일 (2026-10-15)

- 사용자 승인에 따라 게시→검토 중, 내부 draft→in_review→published로 통일했다. 기존 상태 색상·2/2/10 목록·편집·가이드·배포/제출 동작은 유지한다. 검토 시작 안내에는 원본 질문까지 다른 리드에게 공개되어 함께 수정된다는 점을 명시한다.
- 상태/시각/잠금/가이드 및 배포 RPC·컴포넌트·Realtime을 함께 정리했다. 기존 링크의 qStatus는 이전 의미로 호환하고 새 링크는 qStage를 사용한다. 구형 화면 API 요청은 새로고침 안내와 함께 차단한다.
- 로컬 migration 적용과 내용·ID·revision·시각/이력 보존 검증, SQL 25개·관련 JS 164개·타입/린트·Webpack 빌드 통과. 운영 반영/실제 브라우저 검증은 하지 않았다. 운영의 동시 전환 절차와 중단 조건은 questions-operations.md 최신 절을 따른다.

## 현재 위치와 다음 작업

- 학습법·탐구활동의 목록, 작성·수정·읽기 전용 화면과 데이터/API/코드 구조 정리를 진행했다. 현행 계약은 `docs/study/`와 `docs/exploration/`을 따른다.
- 현재 질문·질문지 영역을 공통 컴포넌트로 정리하고 질문지를 단계별 단일 목록으로 통합했다. 실제 화면의 사용자 확인과 후속 조정은 남아 있다.
- 원본 질문·질문지 제작과 응답 화면에 이어 컨설턴트 질문지 목록·학생/컨설턴트 관리·내 정보를 정리했다. 실제 화면의 사용자 확인과 전체 일관성 점검을 이어간다. 로그인·온보딩과 컨설팅 영역은 남아 있다.
- 프로덕션 반영은 전체 개선 작업 마지막에 진행한다. 코드 검증과 실제 브라우저/사용자 검증을 구분한다.

## 합의한 진행 원칙

- UI UX 개선이 주목적이다. 기존 shadcn 컴포넌트를 적절히 수정하고 공통화하여 일관성을 만든다.
- 디자인 시스템 전체를 먼저 구축하는 초기 제안 대신, **현재 화면과 공통 UI를 함께 수정 → 다음 화면에서 영향을 확인하고 필요한 variant·예외를 보완 → 다음 화면** 순서로 진행한다. 사용자는 공통 변경이 다른 화면에 적용되는 것을 허용했다. 현재 화면만 보호하려고 기본 컴포넌트 위에 별도 스타일 래퍼를 늘리지 않는다.
- 데이터 구조와 코드 파일 구조는 해당 화면 개선 중 필요한 부분부터 자연스럽게 정리한다. 대규모 선행 재편은 하지 않는다.
- 모든 변경은 로컬에 누적한다. DB 변경이 필요하면 migration으로 관리하며, 프로덕션 반영은 전체 작업 마지막에 함께 진행한다. 이 방침이 지금 운영 쓰기를 허용하는 것은 아니다.
- 로컬 실행만으로 DB 연결 대상이 로컬로 바뀌지는 않는다. DB 작업 시 실제 연결 대상과 기존 운영 이력을 확인한다.
- 개발 중단 상태인 컨설팅 영역은 마지막 별도 대상으로 둔다. 공유 컴포넌트 변경의 영향은 확인한다.
- 사용자 요청 없이 실제 브라우저 테스트를 하지 않는다. 임시 페이지·가상 데이터 브라우저 테스트도 포함한다.
- 기본 검증은 타입 검사·변경 파일 린트·관련 기존 회귀 검사다. 영향에 따라 빌드를 수행하고 실제 수행 여부를 구분해서 기록한다.
- 기존 권한, 데이터, 저장·제출 계약, 배포 잠금과 입력 보존 정책을 유지한다.

## 질문지 표시 오류 추가 점검 (2026-10-14)

코드·순수 컴포넌트 실행으로 확인한 수정 대기 사항:

1. `QuestionGuideAnswerTable`은 행 이름으로 `find`하여 같은 이름을 가진 두 가이드 행이 첫 답변으로 반복된다. 서로 다른 ID/같은 label/서로 다른 답변의 가상 데이터로 실제 컴포넌트 결과가 첫 답변 두 개임을 재현했다. 행 식별과 표시 이름을 분리해야 한다.
2. `QuestionAnswerTable`의 진로 흐름 읽기 표는 압축된 배열 위치로 rowLabels를 조회한다. 중간 빈 행이 빠진 제출 rows=[id 1,id 3]에서 세 번째 답변에 두 번째 이름이 표시됨을 실제 컴포넌트로 재현했다. 비흐름표 PDF의 순서 기반 라벨도 같은 위험이 있다. 원래 행 위치/이름을 제출 투영까지 보존하는 경로를 함께 검토해야 한다.
3. 일반 가이드·진로 흐름 가이드에서 탐구활동 참조형은 `탐구활동 첨부됨` 문구만 표시하고 상세 링크를 제공하지 않는다. 학습법 분기와 달리 ExplorationReferenceContent 분기가 누락됐다. 리치 텍스트 안의 @참조에는 해당하지 않는다.

이번은 점검이며 위 앱 코드는 아직 수정하지 않았다. 기존 흐름표 회귀 실행기가 새 DetailValue/공통 스타일 import를 인식하도록 테스트 의존성만 보완했다. 흐름표·참조·선택 조건·배치·질문지 목록·PDF 관련 기존 회귀 59개 통과. 위 중복 이름/중간 행 누락은 기존 테스트가 다루지 않던 경우다. 실제 브라우저·운영 데이터·DB 권한 재검증은 수행하지 않았다.

### 진로 흐름 입력 정돈 및 점검 1·2 수정 (2026-10-14)

- 진로 흐름 팝업을 흰 바탕·회색 입력 칸·노란 상단 선·공통 Badge로 정리했다. 모바일 고정 항목 열은 160px, PC는 240px이고 시기 열은 가로로 스크롤한다. 제출 팝업에서 작성 안내·예시·추가·삭제를 숨긴다. 기존 항목/질문 내용과 입력 구조는 유지한다.
