## 현재 위치와 다음 작업

- 사용자는 사이드바 색감을 긍정적으로 확인했다. 모든 상태와 동작의 사용자 검증이 끝났다는 의미는 아니다.
- 사용자는 권한·화면별 디자인 분기 여부와 NEW·숫자 배지 구현을 확인했고, 공통 스타일과 업무 표시 조건의 분리를 설명받았다.
- 학습법 일반 목록 본문의 첫 디자인 개선을 완료했다. 사용자 화면 확인과 후속 조정을 기다린다. 작성·상세 창과 @ 첨부용 목록은 다음 범위로 남겨 두었다.

## 합의한 진행 원칙

- UI UX 개선이 주목적이다. 기존 shadcn 컴포넌트를 적절히 수정하고 공통화하여 일관성을 만든다.
- 디자인 시스템 전체를 먼저 구축하는 초기 제안 대신, **현재 화면과 공통 UI를 함께 수정 → 다음 화면에서 영향을 확인하고 필요한 variant·예외를 보완 → 다음 화면** 순서로 진행한다. 사용자는 공통 변경이 다른 화면에 적용되는 것을 허용했다. 현재 화면만 보호하려고 기본 컴포넌트 위에 별도 스타일 래퍼를 늘리지 않는다.
- 데이터 구조와 코드 파일 구조는 해당 화면 개선 중 필요한 부분부터 자연스럽게 정리한다. 대규모 선행 재편은 하지 않는다.
- 모든 변경은 로컬에 누적한다. DB 변경이 필요하면 migration으로 관리하며, 프로덕션 반영은 전체 작업 마지막에 함께 진행한다. 이 방침이 지금 운영 쓰기를 허용하는 것은 아니다.
- 로컬 실행만으로 DB 연결 대상이 로컬로 바뀌지는 않는다. DB 작업 시 실제 연결 대상과 기존 운영 이력을 확인한다.
- 개발 중단 상태인 컨설팅 영역은 마지막 별도 대상으로 둔다. 공유 컴포넌트 변경의 영향은 확인한다.
- 사용자 요청 없이 실제 브라우저 테스트를 하지 않는다. 임시 페이지·가상 데이터 브라우저 테스트도 포함한다.
- 기본 검증은 타입 검사·변경 파일 린트·관련 기존 회귀 검사다. 영향에 따라 빌드를 수행하고 실제 수행 여부를 구분해서 기록한다.
- 기존 권한, 데이터, 저장·제출 계약, 배포 잠금과 입력 보존 정책을 유지한다.

## 사이드바 변경 기록

### 확인한 기존 구조

- 학습법 페이지 자체에는 사이드바 전용 스타일이 없었다.
- `DashboardShell.tsx`에 로고, 상하단 여백·구분선, 사용자 정보·로그아웃 디자인이 있었다.
- `DashboardNavigation.tsx`에 초록색 검토 요청 배지가 직접 작성되어 있었다.
- 파란 NEW 표시는 질문 기능의 `NewPublicationBadge`를 가져와 사용했다.

### 적용한 변경

- 배경 `#f0f0ed`, 선택 메뉴 `#ffe233`, 선택 글자 `#151515`, hover `#e5e5e0`, 경계 `#d5d5cf`, 포커스 `#68685f`를 사이드바 토큰에 적용했다.
- 어두운 테마도 선택 메뉴는 노랑과 검정 글자를 사용한다.
- MEA 글자를 굵게 표시하고 작은 노란 포인트를 더했다.
- 메뉴 기본 높이를 44px로 조정하고 간격과 모서리를 정리했다.
- 상하단 여백·구분선을 공통 `SidebarHeader`·`SidebarFooter`로 이동했다.
- `SidebarMenuLabel`로 메뉴명의 남은 공간 사용과 말줄임을 공통화했다.
- `SidebarMenuBadge`로 NEW·검토 요청·인원수를 통일했다. 절대 위치 대신 메뉴 내부의 나란한 배치를 사용한다.
- 주 메뉴에 navigation 의미와 현재 링크의 `aria-current`를 추가하고 모바일 메뉴 설명을 한국어로 정리했다.

### 공통 디자인과 업무 로직의 경계

- 색상·크기·모서리·글꼴·메뉴 선택 스타일은 공통 사이드바 컴포넌트가 담당한다.
- `DashboardNavigation`은 권한별 메뉴 선택, 알림 표시 조건, 문구와 숫자를 담당한다. 이는 디자인 분기가 아닌 업무 로직이다.
- `NEW n`: 읽지 않은 질문지 ID 개수, 0이면 숨김. `notification` 배지 사용.
- `검토 요청`: 새 검토 요청이 있을 때 표시. `notification` 배지 사용.
- 학생·컨설턴트 수: 전달받은 수가 있으면 표시하며 0도 표시. `neutral` 배지 사용.
- `notification`은 검정 계열, `neutral`은 옅은 회색 계열이다. 어두운 테마에서는 토큰에 따라 반전된다.
- 로고·사용자 정보·로그아웃의 일부 구성과 스타일은 여전히 모든 대시보드가 공유하는 `DashboardShell`에 있다. 모든 스타일을 기본 UI 파일로 옮겼다고 해석하지 않는다.
- 질문 기능의 `NewPublicationBadge` 자체는 수정하지 않았다. 사이드바에서만 사용을 교체했다.

## 학습법 목록을 기준으로 공통 UI 기본값 정비

- 2026-10-13: 사용자는 다른 화면 영향 방지보다 공통 컴포넌트 자체의 일관된 개선을 우선하도록 명확히 요청했다. 각 화면으로 넘어갈 때 실제 필요한 예외를 추가한다.
- Button 기본값은 노란 배경·검정 글자·작은 모서리·높이40px로 통일했다. 선택용 filter variant는 aria-pressed로 노란 선택 상태를 표시한다. 기존 brand 전용 variant는 기본값으로 흡수했다. sm/xs와 위험·보조·링크 종류는 유지한다.
- Input과 SelectTrigger 기본값은 높이40px·작은 모서리·테두리·배경색으로 통일했다. Select 팝업과 항목도 모서리와 그림자를 정리했다.
- Badge의 공통 모서리를 줄이고 count(개수), subtle(회색), highlight(옅은 노랑)를 추가했다.
- CollectionFilter·CollectionCount·CollectionStatus 래퍼를 제거했다. 학습법 목록은 Button과 Badge를 직접 사용하고 화면에는 배치와 업무 조건만 남긴다. CollectionSearch는 검색 아이콘·배치만 담당하며 Input 스타일은 덮어쓰지 않는다.
- 제목과 빈 화면처럼 여러 요소를 조합하는 CollectionHeader·CollectionEmptyState는 공통 패턴으로 유지했다. 목록 행 배치와 제목·본문 구성은 StudyList의 책임이다.
- 이 변경은 다른 화면의 기본 버튼·입력·선택·배지에도 적용된다. 기존 화면의 명시적 className 덮어쓰기는 각 화면 개선 시 정리한다.
- 타입·변경 파일 lint·diff 공백 검사·Webpack 빌드 통과. 브라우저 테스트·DB 변경·프로덕션 반영 없음.


## 강조 색상 역할 조정

- 2026-10-13: 사용자가 화면 캡처에서 노란 강조가 많다고 지적하여 공통 색상 역할을 조정했다. 이 결정은 직전의 노란 기본 버튼 정책보다 우선한다.
- 노랑은 사이드바 현재 위치와 MEA 포인트에 유지한다. 실행 버튼의 기본값은 primary(밝은 테마에서 검정 배경·흰 글자), 선택용 filter는 회색 배경·테두리·굵은 글자로 표시한다.
- 학습법 추가는 검정, 내/다른 사람 및 전체/사람별 선택은 회색이 된다. 관리자 역할 전환도 같은 filter variant를 사용하고 외곽 그림자를 줄였다.
- 개수 배지에서 노란 선택 배경 전용 글자 덮어쓰기를 제거하여 밝은/어두운 테마 모두 기본 전경색을 따른다.
- 기존 공통 크기·모서리·접근성과 동작은 유지한다. 브라우저 테스트·DB 변경·배포 없음.
- 이번 색상 조정의 타입 검사·변경 파일 lint·diff 공백 검사 통과. 실제 브라우저 확인은 사용자에게 남긴다.


## 색연필 빗금 강조 컴포넌트

- 2026-10-13: 참고 PDF 10쪽의 멘토의 경험·전략 자산·학생의 성장 문구 뒤 노란 사선 강조를 확인했다.
- `components/ui/pencil-highlight.tsx`와 CSS module에 PencilHighlight를 추가했다. marker는 글자 뒤 빗금, underline은 낮은 빗금 밑줄이다. SVG 배경의 비균일한 선을 반복하고 box-decoration-break: clone으로 줄바꿈에 대응한다.
- 의미 있는 강조를 위한 mark 요소이며 글자색·크기는 주변을 상속한다. 강제 색상 모드에서는 밑줄로 대체한다. 브라우저 측 JS·애니메이션·외부 이미지 요청은 없다.
- 학습법 목록 설명에 시험 적용했던 하이라이트는 사용자 요청으로 제거했다. PencilHighlight 공통 컴포넌트와 두 variant는 유지하며 추후 적절한 곳에 사용한다. 현재 선택·오류·저장 상태 표시에는 사용하지 않으며 짧은 핵심 문구와 안내에서만 절제해서 사용한다.
- CollectionHeader의 description은 ReactNode를 받을 수 있도록 확장했다. 기존 문자열 사용도 유지된다.
- 사용 예: `<PencilHighlight>핵심 문구</PencilHighlight>` 또는 `<PencilHighlight variant="underline">핵심 문구</PencilHighlight>`.
- 빗금 SVG의 노랑은 현행 brand 값 #ffe233이다. 추후 브랜드 색 변경 시 이 SVG 색상도 함께 갱신한다.
- 타입·변경 파일 lint·diff 공백 검사·Webpack 빌드 통과. 실제 브라우저 시각 검증·DB 변경·프로덕션 반영 없음.


### 빗금 밑줄 표시 보정

- 사용자 캡처에서 밑줄형이 노란 점 조각처럼 표시됨을 확인했다. 정사각형 SVG를 얕은 배경 크기에 넣어 SVG 기본 비율 유지로 내부 여백이 생기고 선도 지나치게 작아진 것이 원인이다.
- 밑줄 전용 40×14 SVG로 사선을 다시 구성하고 preserveAspectRatio=none으로 타일을 채운다. 배경 높이를 0.7em으로 높여 글자 하단에 겹치게 했다. marker에도 비율 유지 여백을 없앴다.
- 브라우저 검증은 수행하지 않았다. 실제 질감은 사용자 재확인 대상이다.


## 목록 로딩과 shadcn 재사용 점검

- 2026-10-13: 제목과 목록 사이에 조건부로 삽입되던 ‘확정된 학습법을 불러오는 중입니다’ 문구를 제거했다. 로딩 여부가 필터·검색·목록 시작 위치를 밀지 않도록 목록 결과 영역 내부에서만 로딩을 표시한다.
- 결과 영역은 min-height 16rem을 유지하고 초기 데이터가 없으면 공통 CollectionLoadingState의 Skeleton 두 행을 표시한다. 빈 상태도 같은 최소 높이를 사용한다. 실제 데이터가 더 길면 자연스럽게 늘어난다. 브라우저 CLS 측정 완료를 의미하지 않는다.
- 기존 항목이 있으면 원격 로딩 중에도 유지한다. 초기 로컬 저장소 준비와 원격 조회 중에는 개수를 0으로 단정하지 않고 —로 표시한다. 결과 영역에는 aria-busy, 로딩 상태에는 화면 낭독용 문구를 제공한다.
- 공식 shadcn base-luma 레지스트리에서 Empty·Item 원본을 조회하여 로컬 UI로 추가하고 현행 색상·곡률·간격에 맞췄다. 기존 파일 덮어쓰기나 npm 의존성 변경은 하지 않았다.
- Empty는 빈 상태의 아이콘·제목·설명, Item은 행·제목·설명·행동 버튼을 공통화한다. Item의 list variant로 구분선 목록을 지원하고 실제 ul/li 구조를 유지한다. 제목 버튼과 수정·삭제 버튼을 중첩하지 않는다.
- 기존 Skeleton의 모서리를 공통 기준으로 줄이고 reduced-motion 환경에서는 깜빡임을 끈다.
- 도입 보류: InputGroup은 단순 검색 아이콘 하나에 비해 추가 구성량이 커 현재 Input+아이콘 유지. ToggleGroup은 방향키 선택이 필요한 시점에 검토하며 현재 aria-pressed 버튼 유지. DataTable은 정렬·열 기반 비교가 없는 현재 서술형 목록에 부적합하여 보류. AlertDialog는 삭제 확인을 본격 개선할 때 적용 검토.
- 공식 참고: https://ui.shadcn.com/docs/components/base/empty , https://ui.shadcn.com/docs/components/base/item , https://ui.shadcn.com/docs/components/base/input-group , https://ui.shadcn.com/docs/components/base/toggle-group .
- 검증: scripts/verify-study-list.mjs의 로딩·빈 상태·항목 보존·타인 권한 4개와 기존 템플릿 회귀 13개(총17개), 타입·변경 파일 lint·diff 공백 검사·Webpack 빌드 통과. 브라우저 테스트·DB 변경·운영 반영 없음.
