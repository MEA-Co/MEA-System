# 학습법 관리와 질문 참조

학습법 관리는 `/dashboard?view=study`, API는 `/api/study`, 확정 저장은 `public.study`다. 컨설턴트는 본인 확정본, 리드·관리자는 전체 확정본을 읽으며 수정·삭제는 작성자만 가능하다.

## 현재 입력 계약

추가·수정 Drawer의 폼 배경은 중성 회색(bg-muted), 내부 카드는 흰색으로 표시한다. 카드의 노란 상단 선과 회색 입력 필드, 흰색 상단/하단 고정 영역을 유지한다.

- 제목 / 이름은 선택, 최대 100자다. 비어 있으면 학습 전략·기본 정보로 표시 이름을 만든다.
- 문제 상황 카드: 출처 → 학습법 적용 대상·교과·세부 과목명 → 단답형 문제 상황 → 선택 경험 내용 순이다. 세부 과목명은 미적분·확률과 통계처럼 해당 교과 안의 과목명이다.
- 출처는 `self`(자신 또는 지도한 학생의 경험), `template` 두 가지다. 과거 `student`는 `self`로 읽고 저장한다.
- 템플릿은 교과군별 총 56개 문장(국어·영어·수학·기타 각 10개, 사회·과학 각 8개)이다. 목록은 `lib/study/problem-templates.ts`에 있으며 DB 테이블이 아니다. 선택하면 문제 상황·학습법 적용 대상·교과·세부 과목명을 함께 채운다. 시험이 특정되지 않거나 여러 시험에 공통인 상황은 기타, 특정되지 않은 세부 과목명은 비운다. 기존 솔루션과 경험은 유지한다. 기존에 저장한 템플릿 본문을 새 문장으로 자동 교체하지 않는다.
- 선택창에는 고른 템플릿 문구를 표시하며, 본문이나 분류를 직접 수정해도 선택 표시를 유지한다. 다른 템플릿을 선택할 때만 바뀐다. 표시 상태는 블록별로 분리하고 저장 필드는 추가하지 않는다. 임시저장·확정본을 다시 열 때 본문과 일치하는 템플릿을 표시하며, 직접 수정한 본문은 ‘등록한 문제 상황’으로 표시한다.
- 문제 상황은 유형화된 짧은 문장이다. 구체적인 경험은 `values.problemExperience`에 선택 저장한다. UI 시안 단계의 미저장 경험은 DB에 존재하지 않아 소급 복원할 수 없다.
- 대응 솔루션 카드에는 학습 전략, 실천 가이드, 실천 기간 설정을 배치한다. 실천 가이드는 학생이 따라 할 수 있도록 순서·빈도 등을 명확히 작성한다.
- `values.periodEnabled`는 기본 `true`. 해제하면 기간이 없어도 확정할 수 있고 기존 기간 텍스트는 다시 체크할 때 사용하도록 보존한다. 해제 상태의 기간은 상세에서 ‘기간 설정 없음’으로 표시한다.
- 체크리스트는 항목을 추가·수정·삭제한다. 저장 계약은 기존 `values.checklist` 문자열을 유지하며 줄바꿈 하나가 항목 경계다. 기존 긴 서술은 임의로 요약하거나 쪼개지 않는다. 공백만 있는 체크리스트는 확정 불가다.
- 성적 결과 후속 진단·관련 자료 첨부·참고자료 입력 UI는 제거했다. 기존 `resultDiagnosis`, `references`, `reports` 및 Storage 파일은 삭제하지 않고 보존한다. 이번 변경은 파일 삭제나 Storage 정책 변경을 포함하지 않는다.

문제 상황·솔루션·실천 가이드·체크리스트·후속 전략과 분류 항목은 확정 시 필수다. 임시저장은 기존 localStorage/IndexedDB에 유지하며 구형 값은 읽을 때 경험 빈 문자열·기간 설정 true로 보완한다. 새 DB 함수는 구형 클라이언트가 새 필드를 생략할 경우 기존 값을 유지한다. revision 충돌·save ID 재시도·작성자 권한은 유지한다.

## 질문 참조

`@학습법`과 학습법 참조 권장 안내를 유지한다. 독립 학습법 참조형은 제거하고 기존 답변도 본문 언급으로 전환한다. 탐구활동은 파랑·나침반, 학습법은 보라·책으로 구분하며 둘 다 권장일 때 함께 표시한다. 가이드 연결과 기존 접근 권한도 그대로 유지한다. 상세 화면에서 경험 내용과 항목별 체크리스트를 읽을 수 있다.

## 2026-10-12 당시 검증 기록

아래는 당시 기록이며 현재 적용 판단은 [운영 절차](operations.md)의 최신 상태를 따른다.

- 로컬 `20261012024650_study_solution_fields.sql` 적용 완료. 가상 기존 데이터의 원문·체크리스트·진단·첨부 메타데이터·삭제 상태 보존을 이전 리허설 후 롤백으로 검증했다.
- 신규 SQL 저장 회귀, 기존 `study_storage.sql`, `study_guide_reference.sql` 통과. 테스트 데이터는 롤백했다.
- 템플릿/UI/호환 6개와 기존 저장/API/질문 20개 JS 회귀, 타입·변경 파일 린트·Webpack 빌드 통과. 실제 브라우저 테스트는 수행하지 않았다.
- 운영은 읽기 전용 집계와 dry-run만 수행했다. 실제 migration·앱 배포는 하지 않았다. 당시 운영 최신 이력은 `20261012011802`, 학습법 1건(활성 1, student 출처 1, 첨부 0, 후속 진단 내용 0)이었다. 적용 직전에 다시 확인해야 한다.
- 로컬 security advisor 경고 없음, migration 이력 일치. DB lint에는 기존 질문/응답 함수 경고가 있으며 변경한 `save_study` 경고는 없었다.

운영 백업·적용·검증·복구는 [학습법 운영 적용 절차](operations.md)를 따른다.

## 데이터·API 기준 문서

현재 저장 위치·DB 열·권한·검색/페이지·임시저장·새로고침 복원·코드 구조는
[학습법 데이터·API·권한 계약](data-api.md)을 기준으로 한다.
이 문서는 입력과 사용자 흐름을 다루며 같은 구조 설명을 중복 유지하지 않는다.

관리 목록은 전체/확정/임시저장을 선택하고 최대 10개씩 표시한다.
전체에서는 로컬 임시저장이 먼저 나오며 같은 ID의 확정본은 중복 표시하지 않는다.
확정 필터는 실제 확정본을 열고 삭제한다. 참조 선택은 검색·페이지 이동으로 확정본만 선택한다.
학습법 추가는 URL studyEditor=new와 현재 탭의 sessionStorage로 새로고침 후 복원한다.

목록 페이지 이동 UI는 탐구활동과 공통 `CollectionPagination`을 사용한다. 학습법의 검색·페이지 조회는 기존 서버 RPC 계약을 유지한다.

입력·읽기 전용 화면의 섹션 카드는 공통 `Card variant="accent"`를 사용해 질문 카드와 같은 2px 노란색 상단 테두리를 표시한다. 머리글과 본문은 흰 배경이며 회색 구분선·입력 영역은 유지한다. 읽기 전용 내부 항목 라벨은 공통 DetailLabel(14px, 전경색, semibold)로 선명하게 표시한다. 내용은 공통 DetailValue의 입력창과 같은 중성 회색 배경·둥근 모서리·안쪽 여백으로 구분하며 실제 입력 요소가 아닌 정의 목록으로 유지한다. 카드 제목 아래 구분선은 좌우 카드 안쪽 여백만큼 짧게 표시한다.

독립 학습법 첨부형(`kind: study`)은 질문 제작·응답·가이드에서 제거했다. 기존 질문/가이드/제출본은 서술형 본문 참조로 전환하며, 목록 선택기·참조 권장 안내·상세 보기·기존 접근 권한은 유지한다.

## 질문지 안내에서 등록

질문지 처음·질문 사이·마지막에 배치한 안내의 학습법 버튼은 기존 학습법 등록 전용 Drawer를 연다. 안내는 질문이 아니며 등록 개수/완료에 따른 진행·제출 차단은 없다. 질문지 저장 모델은 [질문 문서](../questions/ui.md#질문지-안내)를 따른다.

- 안내의 학습법·탐구활동·탐구줄기 등록 버튼은 공통 Button의 wrap 크기(최소 높이 40px·동일 여백·긴 문구 줄바꿈)를 사용한다. 로딩 중 버튼에도 같은 크기를 적용한다.

## 조회 로딩 UI (2026-10-19)

학습법·탐구활동 첨부 선택 목록은 최초 조회·검색 대기·페이지 이동 중 공통 `AttachmentListSkeleton`으로 제목/요약/상세 버튼 위치를 표시한다. 검색창과 추가·페이지 이동 영역은 유지하며 스크린리더에 로딩 상태를 알린다. 기존 검색·선택·권한·API 계약은 유지한다.

첨부 선택기의 사용자 확인 단계도 `AttachmentPickerSkeleton`으로 검색창·목록·하단 버튼 자리를 표시한다. 첨부 참조 상세 Drawer의 조회 대기는 `AttachmentDetailsSkeleton`으로 카드 형태를 표시한다. 목록 진입 전과 상세 보기에서도 로딩 문구만 단독으로 표시하지 않는다.

목록의 확정 상태는 공통 Badge의 초록색 success 변형으로 표시한다. 데스크톱 상태 열과 모바일 요약에 동일하게 적용하며 임시저장 배지는 기존 강조색을 유지한다.
