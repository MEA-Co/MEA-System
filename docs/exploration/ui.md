# 탐구활동 입력·UI

현재 구현 기준. 저장·권한은 [데이터·API](data-api.md), 적용·검증은 [운영](operations.md)을 참고한다.

## 현재 관리 목록 UI (2026-10-13)

관리 목록은 `ExplorationTable`로 분리했다. 공통 `CollectionHeader`·`CollectionSearch`, shadcn `Tabs`·`Select`·`Table`·`Badge`·`Skeleton`·`Button`을 사용하며 학습법과 같은 중성 회색·흰색 바탕, 검정/노랑 주 행동, 연한 노랑 임시저장 표시를 따른다. 페이지 이동은 학습법과 함께 `components/patterns/collection-pagination.tsx`를 사용한다.

- PC: 주제·기재 영역·상태 또는 작성자·수정일·관리 열. 모바일: 탐구활동 요약과 관리 두 열만 표시하며 가로 스크롤을 요구하지 않는다.
- 내 탐구활동/다른 사람의 탐구활동은 실제 Tabs다. 본인 목록은 전체/확정/임시저장, 타인 목록은 전체 작성자/개별 작성자 Select로 조회한다. 일반 컨설턴트에게 타인 탭은 표시하지 않는다.
- 전체 목록은 본인 로컬 초안을 먼저 표시하고 같은 ID의 확정본을 중복 표시하지 않는다. 확정 필터는 실제 서버 확정본 자체를 열고 삭제한다. 임시저장 삭제는 로컬 초안만 삭제한다.
- 한 페이지 최대 10개다. 확정본의 검색·작성자 필터·정렬·총개수·페이지 보정은 서버 DB에서 처리한다. 브라우저는 현재 페이지 본문만 받으며 로컬 임시저장만 자체 검색한다. 검색 입력은 300ms 후 요청하며 조건 변경 시 첫 페이지로 돌아간다.
- 최초 조회에는 10행 스켈레톤을 표시하고 빈 목록·오류·실제 목록의 표 높이를 유지한다. 목록 밖의 일시적인 로딩 문구는 제거했다. 오류가 나도 임시저장 필터는 사용할 수 있다.
- 행 클릭과 제목/수정·보기 버튼으로 상세를 연다. 버튼 클릭은 행 열기를 중복 실행하지 않는다. 다른 작성자 행은 읽기 전용이며 삭제 버튼이 없다.
- 삭제 대상과 대화상자 열림 상태를 분리해 닫힘 애니메이션 중 안내 문구를 보존한다.
- 질문의 본문 @언급 선택은 본인 확정본을 사용한다. 본인 로컬 수정본이 있어도 기존 확정본을 첨부할 수 있다.
- 화면 `lib/list-model.ts`는 제목·요약 표시, 루트 `lib/exploration/list-query.ts`는 검색 필드·요청 검증·로컬 초안 검색을 담당한다. 저장 훅은 초안/편집/확정·삭제만 담당하며 전체 목록을 읽지 않는다. 작성 Drawer는 아래 입력 UI 계약을 따른다.

## 추가·수정 입력 UI (2026-10-14)

- `ExplorationView`는 Drawer 열림/닫힘·저장 흐름을 연결하고 `components/ExplorationFields.tsx`가 필드 배치를 담당한다. 기본 정보·활동 내용·탐구 과정·성장의 기존 필드 정의, 라벨, 안내문, 필수 조건은 `lib/exploration/fields.ts`를 그대로 사용한다.
- 학습법과 동일한 공통 `DrawerHeader/Title/Description`, `Card`의 `size="sm"` 및 `CardHeader variant="emphasis"`, `Input`·`Textarea`·`Select`·`Label`·`Button`을 사용한다. 중성 회색 폼 배경과 흰 카드, 흰색 머리글과 회색 구분선, 중성 회색의 테두리 없는 입력, 검정 배경/노랑 글자의 주요 버튼을 따른다. 개별 둥근 입력/카드 및 보라·파랑 그라데이션을 제거했다.
- 화면 제목과 필수 안내를 표시한다. `예시 탐구 채우기`는 기존대로 새 활동의 입력값을 예시로 채우는 동작이며 예시 열람 모달로 바꾸지 않았다. 입력/읽기 전용 모두 카드 제목과 필드 라벨의 장식 아이콘을 사용하지 않는다. 첨부·추가·삭제·도움말 등 동작 아이콘과 탐구 과정 화살표만 유지한다.
- 기획→수행→결과는 넓은 화면(lg)에서 3열, 좁은 화면에서는 1열이다. 화살표는 별도의 그리드 칸으로 배치해 절대 좌표에 의존하지 않는다. 작성 가이드는 라벨 오른쪽에 배치하며 공간이 부족할 때만 줄바꿈한다. 과정 3열은 subgrid로 라벨 영역 높이를 공유해 입력칸 시작선을 맞추며 고정 높이로 빈 공간을 만들지 않는다. 기존 Base UI Popover와 공통 Button을 사용한다.
- 보고서 원문 제출·참고 자료도 공통 Card 머리글을 사용한다. 파일 첨부는 회색 드롭 영역과 흰색 버튼, 삭제는 접근 가능한 이름을 가진 빨간색 `−` 버튼이다. 참고자료 추가는 하단 전체 폭의 흰색 버튼이다. 읽기 전용에서도 공유하는 보고서 카드는 같은 디자인을 사용한다.
- 읽기 전용 `ExplorationDetails`도 입력 화면과 `ExplorationSectionCard`를 공유한다. 번호·제목·노란 머리글·구분선·카드 간격이 동일하며, 학년/학기와 기재 유형/영역을 입력 화면과 같은 묶음으로 표시한다. 과정은 PC 3열/모바일 1열과 화살표를 유지하고 라벨 높이를 공유한다. 내용은 입력창처럼 회색 배경과 안쪽 여백을 가진 읽기 전용 정의 목록으로 표시하며 긴 내용의 줄바꿈을 보존한다. 작성용 안내·필수 표시·가이드 버튼은 읽기 전용에 노출하지 않는다. 참고자료는 입력 화면과 같은 번호별 카드/3열 구성을 사용하고 보고서 다운로드와 하단 닫기는 유지한다.
- 하단 저장 안내/닫기/임시저장/확정은 스크롤 중에도 보이는 고정 영역으로 제공한다. 미저장 종료 확인은 Drawer 내부의 공통 AlertDialog를 사용하고 계속 작성 버튼에 초기 포커스를 둔다. 공통 모달의 어두운 배경과 포커스 제어에 더해 확인 중 폼에 `inert`, 스크롤 잠금, fieldset 비활성화를 적용한다. 확인 중 Drawer 닫기를 중복 처리하지 않는다.

## 질문에서 등록·참조

질문의 @ 메뉴는 본인 확정본을 서버 검색·10개 페이지로 표시한다. 선택 ID는 별도 단건 조회로 보존한다. 새 활동은 같은 작성 Drawer를 사용한다. 리치 텍스트에는 explorationReference mark의 UUID와 표시명을 보관하고 상세는 현재 권한으로 읽는다. 생성과 첨부, 직접 읽기와 가이드 참조 예외를 구분한다. 질문 계약은 [질문 문서](../questions/ui.md)를 함께 갱신한다.

## 크기·임시저장 안내

전체 본문이 DB의 2,500,000바이트 제한을 넘으면 첨부 업로드/확정 요청 전에 내용을 줄이라는 오류를 표시한다. 현재 입력은 유지하며 명시적 임시저장의 개별 필드 제한은 기존과 같다. 초안 파일 정리/복구 및 브라우저 호환 범위는 [데이터 계약](data-api.md#브라우저-첨부-정리)을 따른다.

## 추가 창 새로고침 복원 (2026-10-14)

탐구활동 관리 화면에서 새 활동을 만들면 기존 URL의 다른 파라미터를 보존하면서 `explorationEditor=new`를 설정한다. 같은 탭에서 새로고침하면 창을 다시 열고 본문·참고자료·첨부와 마지막 임시저장 기준을 복원한다. 복원 정보가 없는 URL은 빈 추가 창으로 열린다. 기존 활동 수정·읽기 전용 창과 질문의 첨부 선택용 Drawer에는 적용하지 않는다.

본문은 탭별 sessionStorage에 즉시 기록하고 첨부 원문은 별도 IndexedDB에 비동기로 보관한다. 이는 목록에 추가되는 명시적 임시저장과 별개다. 임시저장 후에도 창과 URL을 유지하며, 닫기/변경 내용 버리기/확정 성공 시 URL과 복원 사본을 정리한다. 명시적으로 임시저장한 목록 항목은 닫거나 변경 내용을 버려도 보존한다. 미저장 변경 또는 저장 중의 기존 새로고침/이탈 확인은 유지한다.

복원 저장 실패는 알림으로 안내한다. 파일 저장이 끝나기 전에 강제로 페이지를 나가거나 저장소에 접근할 수 없으면 일부 첨부는 재첨부가 필요할 수 있다. 이 경우 본문과 파일 메타데이터를 유지하고 재첨부 안내를 표시한다. 탭 종료 후에도 계속 보관할 내용은 임시저장을 사용한다.

입력·읽기 전용 화면의 섹션 카드는 공통 `Card variant="accent"`를 사용해 질문 카드와 같은 2px 노란색 상단 테두리를 표시한다. 머리글과 본문은 흰 배경이며 회색 구분선·입력 영역은 유지한다. 읽기 전용 내부 항목 라벨은 공통 DetailLabel(14px, 전경색, semibold)로 선명하게 표시한다. 내용은 공통 DetailValue의 입력창과 같은 중성 회색 배경·둥근 모서리·안쪽 여백으로 구분하며 실제 입력 요소가 아닌 정의 목록으로 유지한다. 카드 제목 아래 구분선은 좌우 카드 안쪽 여백만큼 짧게 표시한다.

독립 탐구활동 첨부형(`kind: exploration`)은 질문 제작·응답·가이드에서 제거했다. 기존 질문/가이드/제출본은 서술형 본문 참조로 전환하며, 목록 선택기·참조 권장 안내·상세 보기·기존 접근 권한은 유지한다.

- 질문지 시작 안내는 탐구활동 등록 버튼을 선택적으로 표시한다. ExplorationView의 registrationOnly 모드로 목록 없이 작성 Drawer를 열며 기존 임시저장·확정·첨부·취소 확인을 재사용한다. 관리 화면 쿼리/복원 상태는 변경하지 않는다.

- 시작 안내의 학습법·탐구활동 등록 버튼은 공통 Button의 wrap 크기(최소 높이 40px·동일 여백·긴 문구 줄바꿈)를 사용한다. 로딩 중 버튼에도 같은 크기를 적용한다.

## 탐구줄기 탭 (2026-10-19)

질문 관리의 질문/질문지와 같은 상위 탐색 구조로 `탐구활동 / 탐구줄기`를 표시한다. 공통 Button의 선택 상태(secondary/ghost)와 Link를 사용하며 `?view=exploration&tab=activities|links`로 이동해 새로고침·뒤로가기에도 선택 영역을 유지한다. 기본값은 탐구활동이다. 기존 내 탐구활동/다른 사람의 탐구활동 탭과 타인 조회 권한은 탐구활동 영역 안에 유지한다.

탐구줄기 영역은 `components/ExplorationLinkView.tsx`가 담당한다. 추가 버튼은 `linkEditor=new` 쿼리로 별도 전체 페이지 작성 화면을 연다. 작성 화면은 기본 정보 카드(필수 이름, required) → 탐구활동 연결 영역 → 별도 설명 카드(선택) 순서로 표시한다. 설명은 이름 카드와 분리하고 연결 영역 아래에 배치한다. 기존 확정 탐구활동을 선택 Dialog에서 검색·10개 페이지로 조회하고, 캔버스 내부 우측 상단의 탐구활동 배치하기 버튼으로 카드를 먼저 추가하고, 카드 좌우 + 연결점을 차례로 클릭하여 선행→후속 화살표를 만든다. 이름만 있는 카드를 열별로 배치하고 왼쪽에서 오른쪽으로 화살표를 표시한다. 열과 관계없이 이미 배치된 카드의 연결점을 이어 1:1·1:N·N:1 연결을 만들 수 있다. 열 수는 제한하지 않으며 React Flow 캔버스에서 카드 드래그·빈 공간 드래그 이동·확대/축소·전체 보기를 제공한다. 화살표의 +는 스킬셋 이름·설명 팝업을 열며, 간선의 −는 연결만 지우고, 카드 제거는 해당 카드와 접속한 화살표를 함께 지운다. 동일 활동의 중복 연결은 막는다. 조회 중에는 공통 목록 스켈레톤, 실패 시 재시도, 검색/목록이 비면 해당 안내를 표시한다.

명시적 임시저장 버튼으로 이 브라우저에 저장한다. 이름을 비워도 저장하며, 나의 탐구줄기 목록에서 검색·10개 페이지·다시 열기·삭제를 제공한다. URL은 `linkEditor=new` 또는 `linkEditor=<초안 UUID>`이며 최초 저장 후 UUID로 교체하되 편집 컴포넌트는 유지하여 현재 카드 위치·확대 비율·캔버스 이동 위치를 보존한다. 반복 저장은 URL을 다시 전환하지 않는다. 저장한 초안은 새로고침 후 복원하고 좌표는 선행 관계에 따라 다시 계산한다. 카드 이동만으로는 미저장 변경이 되지 않는다. 기존 `tab=stems`는 탐구줄기 탭의 호환 별칭으로만 허용한다.

목록 복귀·일반 링크 이동·브라우저 뒤로가기에는 미저장 확인 Dialog를, 새로고침·탭 종료에는 브라우저 기본 이탈 경고를 제공한다. 같은 문서의 히스토리 이동은 라우터 처리 전에 현재 편집 진입점을 복원하고, 계속 작성하면 입력·카드 배치를 유지한다. 나가기를 선택하면 이동하려던 진입점으로 이동한다. 저장 중에는 히스토리 이탈을 막고 저장 완료 후 미저장 변경이 없으면 확인 없이 이동한다. 자동 저장은 아니다. 저장 중 중복 조작을 막고 실패 시 입력을 유지한다. 초안 삭제는 공통 AlertDialog로 확인하며 원본 활동을 삭제하지 않는다. 타인/확정 목록은 DB 연동 전까지 비어 있다.

`ExplorationView`가 영역을 선택하고 `components/ExplorationNavigation.tsx`가 상위 탐색을 담당한다. 질문 첨부 선택기와 등록 전용 화면에는 상위 탐색을 표시하지 않는다.

## 조회 로딩 UI (2026-10-19)

학습법·탐구활동 첨부 선택 목록은 최초 조회·검색 대기·페이지 이동 중 공통 `AttachmentListSkeleton`으로 제목/요약/상세 버튼 위치를 표시한다. 검색창과 추가·페이지 이동 영역은 유지하며 스크린리더에 로딩 상태를 알린다. 기존 검색·선택·권한·API 계약은 유지한다.

첨부 선택기의 사용자 확인 단계도 `AttachmentPickerSkeleton`으로 검색창·목록·하단 버튼 자리를 표시한다. 첨부 참조 상세 Drawer의 조회 대기는 `AttachmentDetailsSkeleton`으로 카드 형태를 표시한다. 목록 진입 전과 상세 보기에서도 로딩 문구만 단독으로 표시하지 않는다.

### 탐구줄기 목록·주차 강조 (2026-10-19)

탐구줄기 상위 탭은 기본 버튼 스타일을 유지하고 우측 상단에 작은 파란색 알림 점(notification dot)을 표시한다. 점 주변은 2.5초 주기로 은은하게 퍼지며, 동작 줄이기 설정에서는 애니메이션을 끈다. 선택 시 secondary 배경으로 구분한다. 그라데이션 배경의 마우스/키보드 포커스 툴팁 `이번 주차에 필요한 블록이에요!`를 표시한다. 관리 목록은 기존 탐구활동과 같은 고정 높이 표·머리글·중앙 빈 상태·검색·필터·페이지 이동 구조를 사용한다. 나의 탐구줄기/다른 사람의 탐구줄기는 기존 canViewOthers 표시 권한을 따르며 타인 목록에서는 상태 대신 작성자를 표시한다. 나의 목록에는 브라우저 초안을 표시하며 타인/확정 목록은 비어 있다. DB 조회·쓰기는 추가하지 않는다.

카드의 상대 위치에 따라 상하/좌우 연결점을 선택하고 곡선 화살표와 스킬셋 + 위치를 함께 갱신한다. 열 배치를 연결 순서로 간주하지 않으며 자기 참조·중복·순환을 만드는 기존 카드만 후보에서 제외한다. 카드 X는 연한 빨강 배경으로 구분한다.

카드 좌우 +는 화살표 연결점이며 눌러도 중앙 정렬 위치를 유지한다. 공통 Button은 눌림 상태에서 위치 이동 대신 밝기로 피드백한다.

캔버스는 `@xyflow/react`를 작성 화면에서 지연 로딩한다. 카드 좌표는 부모의 작성 상태에 보관해 목록으로 돌아갔다가 이어서 작성해도 유지한다. 새 카드는 기존 카드와 겹치지 않는 위치에 배치하고 추가/제거 시 전체 보기를 맞춘다. 드래그 중에는 화면 배율을 재설정하지 않는다. 하단 확대·축소·전체 보기 버튼과 핀치 확대, 카드 키보드 이동을 제공한다. +/삭제 버튼은 드래그 대상에서 제외한다. 일반 휠 스크롤은 페이지를 이동하며 캔버스 이동은 빈 공간 드래그로 수행한다.

캔버스 배경은 연한 회색(muted)에 24px 간격의 옅은 선 격자를 사용해 흰 카드와 구분한다.

- 카드 X 주변의 흰색 ring을 제거했다. 드래그/선택 갱신 시 React Flow 노드의 측정 크기를 유지하고 고정 카드 크기(240×88)를 명시해 재측정 중 숨김을 방지한다. 자동 맞춤은 카드 개수 변경 시에만 실행한다.

활동 배치와 연결을 분리한다. 배치만으로 간선을 생성하지 않으며, 먼저 선택한 +에서 두 번째 +로 방향을 정한다. 간선에는 사용자가 선택한 sourceHandle/targetHandle을 보관해 카드를 이동해도 연결점을 유지한다. 간선 중앙 +는 기존대로 스킬셋 팝업을 연다.

배치하기 버튼은 카드 유무와 관계없이 캔버스 우측 상단 Panel에 고정하며 확대·축소·이동의 영향을 받지 않는다. 캔버스 외부의 중복 버튼은 제거했다.

- 연결은 클릭 방식으로 통일했다. 첫 + 선택 후 포인터를 따라 실선 곡선 화살표를 표시하고 두 번째 카드 +로 확정한다. 카드 본문·빈 공간·다른 UI 누르기 또는 Escape로 취소하며 확대/스크롤 시에도 미완성 연결을 취소한다. 카드 자체 드래그 이동은 유지한다.

- 카드 + 연결점은 손 모양 커서를 사용하고, 마우스 호버/키보드 포커스 시 파란 배경·테두리와 흰 +로 강조한다.

### 단방향 연결 조작

카드 +는 오른쪽 출발점 하나만 표시한다. 이전 탐구의 +를 누른 뒤 후속 카드 본문을 클릭하면 오른쪽→왼쪽 화살표를 만든다. 연결 가능한 카드를 강조하고 연결 중 카드 드래그는 잠시 중지한다. 다른 카드의 +는 출발점 변경이며 도착점으로 사용하지 않는다. 기존 간선도 오른쪽 출발·왼쪽 도착으로 표시한다. 빈 공간/다른 UI/Escape로 취소하며 자기 참조·중복·순환 차단은 유지한다. 이 절이 앞선 양쪽 + 연결 설명을 대체한다.

카드는 오른쪽 32px 버튼 열을 사용하며 위쪽 32px 정사각형 X, 아래 남은 높이 전체에 +를 배치한다. 연결 중 가능한 카드 전체를 미리 강조하지 않고 마우스 호버/키보드 포커스가 있는 대상 카드만 파란 테두리로 표시한다. 카드 본문 클릭으로 연결하고 버튼 조작은 분리한다.

- 연결 미리보기는 실제 간선과 동일한 Bezier 계산·색상·두께를 사용하고 캔버스 배율을 반영한다. 유효한 대상 카드 위에서는 왼쪽 도착점에 맞춰 표시한다. + 버튼에는 공통 Tooltip으로 `후속 탐구 연결하기`를 표시한다.

- 간선 중앙의 − 버튼으로 연결을 즉시 제거한다. 스킬셋 +는 선 중앙보다 40px 위에 분리 배치하고 파란 배경·흰 아이콘과 툴팁으로 강조한다. 원본 탐구활동과 카드는 유지한다.

- 카드/다중 선택 드래그 중 실제 이동 중인 카드에 연결된 간선의 −·스킬셋 + 버튼만 숨기고, 나머지 간선 버튼은 유지한다. 이동 종료 후 짧은 페이드·상승 효과로 다시 표시하고 동작 줄이기 설정에서는 애니메이션을 생략한다. 버튼 위치에는 공통 transition-all 대신 색상 전환만 적용해 좌표가 뒤늦게 따라오는 현상도 방지한다.

### 연결별 스킬셋 입력

간선 + 팝업에서 이름·설명(모두 필수, 각각 최대 200/5,000자)을 입력하거나 현재 초안의 기존 스킬을 선택한다. 적용 시 간선은 skillId로 공유 스킬을 참조한다. 이름이 표시되는 버튼에는 툴팁을 표시하지 않고 hover 시 수정하기로 바꾸며 흰 배경 X는 해당 연결의 스킬 참조만 해제한다. 간선 제거 후에도 스킬은 재사용 목록에 남는다. 스킬과 연결은 줄기 임시저장에 포함되며 확정 시 DB에도 저장한다.

### 연계 스킬 재사용

스킬셋 명칭을 연계 스킬로 변경했다. 팝업은 기존 스킬 선택(이름/설명 검색·사용 연결 수)과 새 스킬 만들기로 구분한다. 현재 연결된 스킬은 별도로 표시하고 내용 수정 시 같은 스킬을 쓰는 모든 연결에 반영됨을 안내한다. 현재 작성 중인 줄기의 스킬과 본인이 다른 줄기에서 확정한 스킬을 재사용할 수 있다. 연결/카드를 삭제해도 스킬 목록은 보존한다. 이 계약이 이전 연결별 스킬셋 사본/삭제 설명을 대체한다.

탐구활동 배치·연계 스킬 팝업은 공통 DialogContent의 rounded-lg 기본 모서리를 사용한다.

- 연계 스킬 팝업 제목은 추가/수정 모두 `탐구활동 연계 스킬셋`으로 표시하고, 제목 아래 활동명→활동명 설명은 제거했다.

- 연계 스킬은 이름과 설명 모두 필수다. 설명 입력에 required/필수 표시를 적용하고 공백만 입력한 경우에도 추가·수정 적용을 막는다. 탐구줄기 자체의 설명은 계속 선택이다.

- 연계 스킬이 배치된 간선은 파란 + 대신 스킬 이름 버튼으로 표시한다. 이름은 말줄임 없이 표시하며 수정하기 문구와 비교해 긴 쪽에 너비를 맞춘다. 클릭하면 기존 팝업을 열며, 툴팁과 접근 가능한 이름에 스킬 이름·수정 동작을 안내한다.

- 스킬 이름 버튼은 독립 ExplorationSkillEditDialog를 열어 이름·설명을 바로 수정한다. 추가용 탭/검색/현재 연결 요약은 수정 화면에서 제거했다. 여러 연결에서 공유할 때만 일괄 반영 안내를 표시한다. 하단의 다른 스킬로 변경은 별도 선택 화면으로 전환하고, 취소는 변경을 적용하지 않는다. 공통 Dialog·Input·Textarea·Button을 사용한다.

- 스킬 이름 버튼은 툴팁 없이 표시하고, 스킬이 없는 + 버튼에만 연계 스킬 추가 툴팁을 유지한다.

- 연계 스킬 추가·수정 팝업의 데스크톱 최대 폭을 xl(36rem)로 넓혔다. 모바일 화면 여백과 최대 높이/내부 스크롤은 유지한다.

- 스킬 이름 버튼 호버/키보드 포커스 시 우측 상단 X로 해당 간선의 스킬만 해제한다. 화살표·스킬 원본·다른 간선의 재사용은 유지하며 해제 후 +로 돌아간다. 터치 기기에서는 X를 항상 표시한다.

- 스킬 해제 X는 흰 배경을 사용한다. 스킬 이름 버튼 호버/키보드 포커스 시 수정하기 문구로 바뀌며, 겹친 grid 텍스트로 버튼 폭과 위치를 유지한다.

- 스킬 이름 버튼의 최대 너비·말줄임을 제거하고 max-content 겹침 grid로 스킬 이름/수정하기 중 긴 문구에 너비를 고정한다. 호버 시 텍스트만 바뀐다.

### 다른 화면과의 격리 점검 (2026-10-19)

`ExplorationView`는 URL 영역만 선택하며 활동 관리와 탐구줄기를 별도 하위 컴포넌트로 마운트한다. 탐구줄기를 표시할 때 `useExplorationStorage`를 실행하지 않아 숨은 활동 초안 복원·sessionStorage 기록·이탈 경고가 섞이지 않는다. `explorationEditor=new`가 URL에 함께 남아 있어도 활동 편집기를 뒤에서 복원하지 않는다. 질문 첨부 선택/등록 전용 모드는 URL tab과 무관하게 기존 활동 화면을 사용한다.


### 캔버스 커서 (2026-10-19)

배경·이동 가능한 카드는 grab, 실제 카드 드래그는 grabbing, 버튼과 연결 가능한 후속 카드는 pointer로 표시한다. 연결선은 선택/포커스/포인터 이벤트와 BaseEdge의 기본 20px 투명 클릭 영역을 제거해 배경 이동을 가로채지 않는다. 연결 편집은 별도 +/스킬/− 버튼에서 처리한다. 연결 미리보기 중 금지 대상은 not-allowed를 유지한다.


### 탐구줄기 확정·조회 (2026-10-19)

- 하단에 임시저장/확정하기를 구분한다. 이름과 연결 1개 이상이 있어야 확정할 수 있다. 스킬 팝업의 미적용 입력이 있으면 저장을 막고 먼저 적용하도록 한다. 확정에서 제외되는 고립 활동 개수를 표시한다.
- 임시저장은 고립 활동도 보관한다. 확정 성공 시 DB에 연결된 활동만 남기고 현재 화면에서도 고립 활동을 제외한다. 남은 카드의 화면 위치는 유지하며 다시 열면 관계 기반으로 자동 배치한다.
- 성공한 확정의 로컬 초안만 revision 확인 후 정리한다. 다른 탭의 수정/저장소 접근 실패는 초안을 보존하고 경고한다. 저장 중 이탈 차단, 실패 시 입력 보존, 최초 저장 시 캔버스 인스턴스 유지가 계속 적용된다.
- 전체 목록은 초안과 확정본을 합쳐 10개씩, 임시저장 필터는 이 브라우저 초안, 확정 필터는 DB 확정본을 표시한다. 초안이 있어도 확정 필터에서 최신 DB 내용을 별도로 열 수 있다. 목록 검색·상세·스킬 목록에는 로딩 스켈레톤과 실패 재시도를 제공한다. 자동 polling은 없다.
- 리드/관리자의 다른 사람 목록은 읽기 전용이다. 기본 정보는 읽기 전용, 카드 배치/연결/제거 버튼은 숨긴다. 캔버스 이동·확대/축소·카드 위치 이동과 스킬 이름 클릭 후 설명 읽기는 가능하다. 위치는 저장하지 않는다.
- 기존 스킬 선택 팝업은 현재 줄기 스킬과 본인이 확정한 스킬 목록(이름 검색·10개 페이지)을 구분한다. 선택만으로 DB를 쓰지 않는다. 새 스킬과 내용 수정은 줄기 확정 시 함께 저장한다. DB 스킬 수정 시 다른 줄기의 공유 참조에도 반영됨을 알린다. 스킬 내용의 동시 수정 충돌은 전체 저장을 중단한다.
- 실제 브라우저의 커서 전환 제보는 사용자가 개발자 도구 검사 모드 때문이었음을 확인했다. 새로고침이나 추가 커서 수정은 필요하지 않았다.


### 확정 시 연결별 스킬 필수 (2026-10-19)

확정하기를 누를 때 스킬 없는 연결이 있으면 “연계 스킬이 없는 연결이 N개 있어요. 모든 연결에 스킬을 할당해 주세요.” 오류 토스트를 표시하고 API 요청을 보내지 않는다. 연결/입력/임시저장은 유지한다. 모든 연결에 스킬이 있어야 DB 확정이 가능하며, 작성 중 임시저장은 스킬 없이도 가능하다.


확정 버튼은 저장 중에만 비활성화한다. 이름 미입력·연결 없음·스킬 팝업 미적용·스킬 미할당은 버튼 클릭 후 구체적인 이유를 토스트로 안내하며 API 요청을 보내지 않는다.


확정 버튼은 저장 중 또는 마지막 DB 확정본과 내용이 같을 때 비활성화한다. DB 확정 기준을 임시저장 기준과 별도로 유지하므로 수정 내용을 임시저장해도 확정 버튼은 활성 상태다. 신규/재개한 초안은 확정 가능하며 입력 누락은 클릭 시 토스트로 안내한다. 카드 좌표 이동은 저장 변경사항에 포함하지 않는다.


확정 직후 이탈 판단은 DB 원본 JSON 문자열이 아니라 화면과 동일한 노드/간선 구성·표시명 정규화로 비교한다. JSONB 속성 순서나 활동 제목 앞뒤 공백 때문에 미저장 경고가 발생하지 않으며, 확정 후 실제로 수정하면 다시 경고한다.


### 스킬 선택 팝업·탐구줄기 표 정렬 (2026-10-19)

스킬 검색은 현재 줄기와 DB 목록 모두 이름 기준이며 결과에 설명을 표시하지 않는다. 기존 스킬 영역은 416px로 고정하고 검색/로딩/오류/빈 결과에 같은 공간을 사용한다. 현재 줄기와 DB 결과는 하나의 내부 스크롤 영역에 배치한다. 최초 조회는 이름 행 형태의 스켈레톤, 후속 검색/페이지 조회는 기존 결과를 흐리게 유지하고 선택을 일시 차단한다. 새 스킬 작성 영역은 344px이며 두 모드 사이 높이는 220ms 애니메이션으로 전환한다. 동작 줄이기 설정에서는 즉시 전환한다. 작은 화면에서는 공통 Dialog의 최대 높이와 스크롤을 유지한다.

탐구줄기 표는 탐구활동/학습법과 같은 행 클릭 진입·이름 버튼·관리 아이콘 방식을 쓴다. 본인은 Pencil/Trash2, 타인은 Eye를 표시하고 접근 가능한 이름을 제공한다. 내부 버튼 클릭은 행 클릭과 중복 처리하지 않으며 삭제 클릭으로 편집 화면이 열리지 않는다. 모바일 80px/데스크톱 60px 행 높이와 관리 열 폭도 맞춘다.


### 기존 스킬 선택 표 (2026-10-19)

기존 스킬은 공통 Table/CollectionPagination을 사용하는 이름·선택 아이콘 열로 표시한다. 행·이름·+ 버튼으로 선택하며 이름은 키보드로도 선택 가능하다. 범위 선택에서 현재 탐구줄기(로컬)와 내가 확정한 스킬(DB)을 전환하고 각각 10개씩 페이지를 표시한다. 현재 줄기 스킬이 있으면 해당 범위로 시작한다. DB 범위에서만 페이지를 조회하며 전체 DB 목록을 가져오지 않는다. 검색·범위 변경은 첫 페이지로 이동하고 로딩·오류·빈 결과도 고정 표 영역을 유지한다. 설명은 표시하지 않는다. 기존 두 목록 동시 표시를 이 방식으로 대체한다.


스킬 범위 SelectValue에 한글 표시명을 명시해 메뉴를 열기 전에도 current/saved 내부 값이 노출되지 않도록 한다.


연계 스킬 신규 입력의 이름 플레이스홀더는 “예: 이론 to 사례”, 설명은 “기초 이론, 기반이 되는 배경 이론 등을 탐구한 후 해당 이론이 적용된 실제 사례 탐구/실험/개발로 후속 연계”로 표시한다.

탐구줄기 목록의 확정 상태는 공통 Badge의 success 변형(초록색)으로 표시해 임시저장 상태와 구분한다.

목록의 확정 상태는 공통 Badge의 초록색 success 변형으로 표시한다. 데스크톱 상태 열과 모바일 요약에 동일하게 적용하며 임시저장 배지는 기존 강조색을 유지한다.

질문지 안내에 탐구줄기 등록 버튼을 표시할 수 있다. 현재 질문지 작성 내용을 저장한 뒤 탐구줄기 새 등록 페이지로 이동하며 저장 실패 시 질문지에 머문다. 질문지 처음·질문 사이·마지막 위치 모두 같은 동작을 사용한다.
