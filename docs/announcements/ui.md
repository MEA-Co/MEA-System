# 서비스 공지 UI

관리자 대시보드의 기타 → 서비스 공지(`?view=announcements`)에서 제목·내용·표시 시작/종료를 입력하고 저장한다. 날짜는 현재 기기의 시간대로 입력하며 API에는 UTC ISO로 전달한다. 시작을 비우면 즉시, 종료를 비우면 수동 종료까지 표시한다. `공지 표시`를 해제하거나 `현재 공지 종료`로 종료한다. 종료 버튼은 저장된 공지를 종료하며 편집 중인 미저장 문구는 게시하지 않는다.

공통 CollectionHeader, Card, Label, Input, Textarea, Checkbox, Button, Skeleton을 사용한다. 저장 로딩은 버튼 내부, 오류는 확보한 영역에 표시한다. 충돌 시 입력을 유지하며 명시적으로 입력을 버리고 최신 공지를 불러올 수 있다. 저장 성공 시 서버 최신 revision을 반영한다.

로그인한 사용자의 private 화면(대시보드·질문지 응답·컨설팅 등)에 화면 전체 너비의 얇은 고정 상단 공지 띠를 표시한다. 확성기 아이콘 → 제목 → 구분점 → 본문 → 닫기 순서이며 옅은 노란 사선 배경과 하단 경계선을 사용한다. 제목과 본문은 같은 줄에서 이어지고 좁은 화면에서는 자연스럽게 줄바꿈한다. 공지는 viewport 최상단에 fixed로 배치하고 본문 앞에는 같은 높이의 자리 요소를 한 번만 둔다. sticky와 fixed 좌표계를 섞지 않아 스크롤 중에도 공지와 사이드바의 위치 기준이 같다. ResizeObserver로 높이를 공유하여 고정 사이드바와 관리자 역할 전환 버튼도 공지 아래에 배치한다. 닫기·기간 종료 시 공간을 회수하며 작성 화면은 재마운트하지 않는다. 길어진 본문은 내부 스크롤, 제목은 줄바꿈한다. 포커스 이동·페이지 새로고침·작성 화면 재마운트는 하지 않는다. aria-live polite로 안내한다.

닫기는 현재 컴포넌트의 해당 revision에만 적용한다. 변경된 공지는 다시 보이며 새 접속/새로고침에도 다시 표시한다. 관리자 저장은 Postgres Changes를 받아 원문을 재조회한다. 구독 연결 직후·탭 복귀·포커스·온라인 복구·보이는 탭의 30초 간격으로도 재확인한다. 시작/종료 경계는 수신한 일정과 기기 시간으로 1초 간격 판정한다. 따라서 기기 시계 오차가 있으면 예약 노출 시각에 차이가 날 수 있다. 실시간 연결 실패 시 갱신 지연은 보완 조회에 의존한다. 일시적인 통신 실패는 마지막 공지를 유지하며 인증 해제 시 제거한다.

공지 기능은 안내만 제공한다. 점검 모드, 제출 차단, 자동 저장, 브라우저 초안 복구를 추가하지 않는다. 기존에 열려 있는 구버전 앱에는 최초 기능 배포만으로 배너가 생기지 않으며, 새 버전을 연 후부터 공지 변경을 수신한다.

관리자도 동일한 상단 공지의 표시 대상이다. 관리자 화면에서 저장·종료 성공 시 같은 탭의 공지 배너에 갱신 이벤트를 전달하여 즉시 서버 최신 값을 조회한다. 비활성/예약/종료 및 현재 revision 닫기 정책은 유지한다.

공지 편집에서 빨강·노랑·초록을 라디오 버튼으로 선택한다. 색상 이름과 확성기를 함께 표시하고 미리보기/실제 공지에 동일한 배경·테두리·아이콘 색상을 적용한다. 기존 공지는 노랑이다.


공지 미리보기와 실제 표시는 `AnnouncementBanner`를 공유한다. 사선 배경·중앙 정렬·글자색·아이콘·닫기 버튼까지 동일하며 미리보기 닫기는 실제 공지를 닫거나 저장하지 않는다. 표시 영역의 너비 차이에 따른 줄바꿈은 해당 영역에 맞춘다.
